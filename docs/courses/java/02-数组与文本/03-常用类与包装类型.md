# 常用类与包装类型

## 学习目标

- 理解 `Object` 的 `equals`、`hashCode`、`toString` 契约，并能写值对象。
- 正确使用包装类型、解析方法、`Math`、`BigInteger` 和 `BigDecimal`。
- 用 `Optional` 表达可能缺失的返回结果，同时处理外部输入错误。

## 核心知识点

### 专业术语

- **Object 契约**：`equals` 表示逻辑相等，`hashCode` 为相等对象提供相同哈希值，`toString` 提供可读表示。
- **包装类型（wrapper type）**：`Integer`、`Long`、`Boolean` 等对象类型，能用于泛型并可表达 `null`。
- **解析（parse）**：`Integer.parseInt` 等方法把文本转换为基本值；格式非法通常抛 `NumberFormatException`。
- **`BigInteger`/`BigDecimal`**：任意精度整数/十进制数，适合超出基本类型范围或要求精确小数的场景。
- **`Optional<T>`**：明确表达“可能有一个 T，也可能没有”的返回容器，不是通用的空值替代品。

### 白话解释与边界

重写 `equals` 时必须同时保持 `hashCode` 一致，否则对象放进 `HashSet` 或作为 `HashMap` 键后可能找不回来。值对象应使用稳定字段参与比较，并让 `toString` 不泄露敏感信息。包装类型服务于集合和可空输入，但自动拆箱 `null` 会失败；解析外部文本时要把格式异常转成清晰的错误反馈。

`BigInteger` 提供任意精度整数运算，但对象和计算成本高于基本整数；`BigDecimal` 应从字符串或整数构造，并在除不尽时指定舍入模式。`Math` 的普通运算可能溢出，`addExact` 等检查方法会在溢出时抛异常。`Optional` 更适合作为查询方法的返回值，调用方通过 `map`、`orElse` 或 `orElseThrow` 选择缺失语义，而不是到处调用 `get()`。

## 简单案例

```java
import java.math.BigDecimal;
import java.util.Objects;
import java.util.Optional;

public class CommonTypesDemo {
    static final class UserId {
        private final String value;

        UserId(String value) {
            if (value == null || !value.matches("U-\\d+")) {
                throw new IllegalArgumentException("invalid user id");
            }
            this.value = value;
        }

        @Override
        public boolean equals(Object other) {
            return other instanceof UserId id && value.equals(id.value);
        }

        @Override
        public int hashCode() {
            return Objects.hash(value);
        }

        @Override
        public String toString() {
            return "UserId[" + value + "]";
        }
    }

    static Optional<UserId> parse(String text) {
        try {
            return Optional.of(new UserId(text));
        } catch (IllegalArgumentException error) {
            return Optional.empty();
        }
    }

    public static void main(String[] args) {
        UserId first = new UserId("U-42");
        UserId same = new UserId("U-42");
        BigDecimal total = new BigDecimal("0.10").add(new BigDecimal("0.20"));
        System.out.println("equal=" + first.equals(same) + ", hash=" + (first.hashCode() == same.hashCode()));
        // 输出：equal=true, hash=true
        System.out.println("total=" + total + ", missing=" + parse("bad").orElse(null));
        // 输出：total=0.30, missing=null
    }
}
```

输出会显示 `equal=true`、`hash=true` 和 `total=0.30`。`parse` 把非法输入转成空结果，调用方明确使用 `orElse` 取默认值；真实服务也可以用 `orElseThrow` 转成带上下文的领域异常。

## 易混点

- `equals` 为真必须意味着 `hashCode` 相同，但哈希相同不代表对象一定相等；只重写一个会破坏集合查找。
- `new BigDecimal(0.1)` 携带浮点近似误差，金额应从字符串构造并明确舍入。
- `Optional.empty()` 表示缺少返回值，不等于允许对 `Optional` 本身使用 `null` 或无条件 `get()`。
- `Math.addExact` 会检查整数溢出，普通 `+` 可能静默回绕；是否抛错取决于所选 API。

## 课后小问

1. 为什么 `UserId("U-42")` 的两个实例可以相等？
答案：`UserId` 按稳定的 `value` 字段重写了 `equals`，并按相同字段计算 `hashCode`。
解析：值对象关心内容而不是对象身份；保持 equals/hashCode 契约后，它才能安全地作为集合元素或 Map 键。

2. 查询方法返回 `Optional<UserId>` 时，调用者该如何处理缺失值？
答案：根据业务选择 `orElse`、`orElseGet` 或 `orElseThrow`，明确默认、延迟计算或异常策略。
解析：`Optional` 的价值是把“可能没有”放到返回类型中，调用者必须作出选择；直接 `get()` 只是把问题推迟成异常。

## 本节小结

- `Object` 的相等、哈希和字符串表示契约决定对象能否可靠进入集合。
- 包装类型适合泛型和可空输入，但自动拆箱与缓存身份都有边界。
- `BigInteger` 和 `BigDecimal` 解决范围或十进制精度问题，构造和舍入方式必须明确。
- `Optional` 表达查询缺失，解析外部输入仍要捕获并翻译格式错误。
