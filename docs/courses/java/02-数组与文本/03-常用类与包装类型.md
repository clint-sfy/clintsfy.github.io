# 常用类与包装类型

## 学习目标

- 理解包装类型与基本类型、自动装箱/拆箱和 `null` 风险。
- 使用 `Integer`、`Long`、`Double`、`Boolean`、`Character` 完成解析和格式转换。
- 使用 `Objects` 表达安全比较和前置校验，用 `Optional` 表达查询结果可能缺失。
- 能根据需求转到[大数与精确计算](/courses/java/02-数组与文本/06-大数与精确计算)选择 `BigInteger`、`BigDecimal` 或检查溢出的 `Math` API。

## 核心知识点

### 专业术语

- **包装类型（wrapper type）**：`Integer`、`Long`、`Boolean` 等对象类型，能用于泛型并可表达 `null`。
- **自动装箱与拆箱（boxing/unboxing）**：基本值与包装对象之间由编译器插入的转换，拆箱 `null` 会抛 `NullPointerException`。
- **解析（parse）**：`Integer.parseInt` 等方法把文本转换为基本值；格式非法通常抛 `NumberFormatException`。
- **`Objects` 工具类**：提供空值安全比较、哈希、字符串和前置条件检查。
- **`Optional<T>`**：明确表达“可能有一个 T，也可能没有”的返回容器，不是通用的空值替代品。

### 白话解释与边界

包装类型像“可以放进集合的盒子”，可以有 `null`，但不应因为自动装箱就忘记空值边界。`Integer.parseInt` 返回基本 `int`，失败会抛异常；`Integer.valueOf` 返回对象，缓存只是一种实现优化，不能用 `==` 判断数值。外部输入解析要捕获并翻译格式错误。

`Optional` 更适合作为查询方法的返回值，调用方通过 `map`、`orElse` 或 `orElseThrow` 选择缺失语义，而不是到处调用 `get()`。它不能替代字段、参数和集合的空值设计；`Optional` 本身通常也不应存进实体字段或序列化协议。

## 常用用法

### `Integer.parseInt`/`Long.parseLong`：解析整数文本

```java
int count = Integer.parseInt("42");
long id = Long.parseLong("9000000000");
System.out.println(count + ", " + id);
// 输出：42, 9000000000
```

解析失败或超出目标类型范围会抛 `NumberFormatException`；来自请求、文件或命令行的文本要先做格式和范围错误处理。

### `Integer.valueOf`/`Long.valueOf`：得到包装对象

```java
Integer count = Integer.valueOf("42");
Long id = Long.valueOf(42L);
System.out.println(count.getClass().getSimpleName() + ", " + id);
// 输出：Integer, 42
```

需要对象类型、泛型参数或可空值时使用包装类型；数值比较用 `equals` 或 `compareTo`，不要依赖包装对象缓存的身份。

### `Integer.toString`/`Long.toString`：数值转文本

```java
String decimal = Integer.toString(42);
String hex = Integer.toHexString(255);
String binary = Long.toBinaryString(5L);
System.out.println(decimal + ", " + hex + ", " + binary);
// 输出：42, ff, 101
```

格式化协议字段时明确进制和补位规则；`toString` 只是表达，不负责校验字符串能否被业务接受。

### `Boolean.parseBoolean`/`valueOf`：解析布尔值

```java
boolean enabled = Boolean.parseBoolean("true");
Boolean boxed = Boolean.valueOf("yes");
System.out.println(enabled + ", " + boxed);
// 输出：true, false
```

`parseBoolean` 对不区分大小写的 `"true"` 返回真，其他文本通常返回假，不会报告拼写错误；严格协议应先校验允许值。

### `Double.parseDouble`/`isFinite`：解析浮点文本

```java
double rate = Double.parseDouble("0.25");
System.out.println(rate + ", " + Double.isFinite(rate));
// 输出：0.25, true
```

浮点数可能有二进制精度误差，也可能出现 `NaN`、正负无穷；金额和需要十进制精度的数值转到 `BigDecimal` 页面。

### `Character.isDigit`/`isLetter`：判断字符类别

```java
char value = '中';
System.out.println(Character.isLetter(value) + ", " + Character.isDigit(value));
// 输出：true, false
```

这些方法按 Unicode 字符属性判断，不等于只判断 ASCII；若协议只允许 ASCII，应显式写范围或正则规则。

### 自动装箱/拆箱：在基本值与对象间转换

```java
Integer boxed = 42;
int primitive = boxed;
System.out.println(boxed + ", " + primitive);
// 输出：42, 42
```

拆箱 `null` 会抛 `NullPointerException`；集合读取、数据库字段和配置输入要先判断空值，不要让隐式转换掩盖错误。

### `Objects.equals`：安全比较可能为 null 的值

```java
String left = null;
String right = "Java";
System.out.println(Objects.equals(left, right));
// 输出：false
```

`Objects.equals` 在一方或双方为 `null` 时安全返回结果；它只比较内容，不替代业务上的大小写、规范化或版本规则。

### `Objects.hash`：组合字段计算哈希

```java
int hash = Objects.hash("U-42", 18);
System.out.println(hash != 0);
// 输出：true
```

适合在值对象的 `hashCode` 中组合字段；参与 `equals` 的字段必须和参与 `hashCode` 的字段保持一致。

### `Objects.requireNonNull`：校验必填引用

```java
String name = Objects.requireNonNull("Ann", "name");
System.out.println(name);
// 输出：Ann
```

参数为 `null` 时立即抛 `NullPointerException`，适合构造器和方法入口；异常信息应指出字段名，不能把校验拖到更深层才失败。

### `Optional.of`/`ofNullable`/`empty`：创建可选结果

```java
Optional<String> present = Optional.of("Java");
Optional<String> maybe = Optional.ofNullable(null);
Optional<String> missing = Optional.empty();
System.out.println(present.isPresent() + ", " + maybe.isEmpty() + ", " + missing.isEmpty());
// 输出：true, true, true
```

`of` 不接受 `null`，`ofNullable` 会把 `null` 变成空容器；`Optional.empty()` 表达“没有结果”，不等于允许对 `Optional` 本身使用 `null`。

### `orElse`/`orElseGet`/`orElseThrow`：处理缺失值

```java
Optional<String> value = Optional.empty();
String eager = value.orElse("default");
String lazy = value.orElseGet(() -> "computed");
String required;
try {
    required = value.orElseThrow(() -> new IllegalArgumentException("missing"));
} catch (IllegalArgumentException error) {
    required = "handled";
}
System.out.println(eager + ", " + lazy + ", " + required);
// 输出：default, computed, handled
```

示例捕获了 `orElseThrow` 的异常以展示三种结果；实际使用时按业务选择默认值、延迟计算或异常。`orElse` 的默认表达式会先计算，昂贵计算优先 `orElseGet`。

### `Optional.map`/`filter`：链式转换与筛选

```java
Optional<String> input = Optional.of(" java ");
Optional<Integer> length = input.map(String::strip).filter(value -> !value.isEmpty()).map(String::length);
System.out.println(length.orElse(0));
// 输出：4
```

链式操作会在空结果上短路；转换函数不应借机吞掉异常或产生含义不清的嵌套 `Optional`。

## 不常用但需要知道

### `Optional.ifPresent`/`ifPresentOrElse`：按有无执行动作

```java
Optional<String> value = Optional.of("Java");
value.ifPresentOrElse(
    item -> {
        System.out.println(item);
        // 输出：Java
    },
    () -> {
        System.out.println("missing");
        // 输出：missing
    });
```

适合边界处做一次性动作；复杂业务流程不要堆叠 lambda，必要时恢复成清晰的 `if` 或领域方法。

### `Optional.flatMap`：避免嵌套 Optional

```java
Optional<String> text = Optional.of("42");
Optional<Integer> number = text.flatMap(value -> {
    try {
        return Optional.of(Integer.parseInt(value));
    } catch (NumberFormatException error) {
        return Optional.empty();
    }
});
System.out.println(number.orElse(0));
// 输出：42
```

当映射函数本身返回 `Optional` 时使用 `flatMap`；异常边界要有统一策略，不能用空结果掩盖所有输入错误。

### `Optional.stream`：把可选结果接入 Stream

```java
long count = Stream.of(Optional.of("a"), Optional.<String>empty())
    .flatMap(Optional::stream)
    .count();
System.out.println(count);
// 输出：1
```

适合把多个可选查询结果汇入流；单个值的简单分支不必为了使用 Stream 而增加复杂度。

### `Integer.compare`/`compareUnsigned`：比较整数

```java
System.out.println(Integer.compare(2, 10) < 0);
// 输出：true
System.out.println(Integer.compareUnsigned(-1, 1) > 0);
// 输出：true
```

`compareUnsigned` 按无符号视角比较，适合协议序号或位运算场景；普通业务数字通常使用有符号比较。

### `Math` 检查与取整：选择更合适的数值页

```java
int total = Math.addExact(20, 22);
long page = Math.floorDiv(-7, 3);
System.out.println(total + ", " + page);
// 输出：42, -3
```

这里只展示入口；溢出检查、`BigInteger`、`BigDecimal`、舍入和金额边界集中在[大数与精确计算](/courses/java/02-数组与文本/06-大数与精确计算)。

## 简单案例

```java
import java.math.BigDecimal;
import java.util.Objects;
import java.util.Optional;

public class CommonTypesDemo {
    static final class UserId {
        private final String value;

        UserId(String value) {
            this.value = Objects.requireNonNull(value, "value");
            if (!value.matches("U-\\d+")) {
                throw new IllegalArgumentException("invalid user id");
            }
        }

        @Override
        public boolean equals(Object other) {
            return other instanceof UserId id && value.equals(id.value);
        }

        @Override
        public int hashCode() {
            return Objects.hash(value);
        }

        @Override
        public String toString() {
            return "UserId[" + value + "]";
        }
    }

    static Optional<UserId> parse(String text) {
        try {
            return Optional.of(new UserId(text));
        } catch (IllegalArgumentException error) {
            return Optional.empty();
        }
    }

    public static void main(String[] args) {
        UserId first = new UserId("U-42");
        UserId same = new UserId("U-42");
        BigDecimal total = new BigDecimal("0.10").add(new BigDecimal("0.20"));
        System.out.println("equal=" + first.equals(same) + ", hash=" + (first.hashCode() == same.hashCode()));
        // 输出：equal=true, hash=true
        System.out.println("total=" + total + ", missing=" + parse("bad").orElse(null));
        // 输出：total=0.30, missing=null
    }
}
```

案例把包装无关的领域 ID 校验、`Objects` 前置检查、值对象相等和 `Optional` 查询结果放在一起；金额细节请查大数专题。

## 易混点

- 包装类型的 `==` 可能受缓存影响；数值内容比较使用 `equals` 或 `compareTo`。
- 自动拆箱 `null` 会抛 `NullPointerException`，集合和外部输入边界要先判断。
- `parseInt` 返回基本值并可能抛格式异常，`valueOf` 返回包装对象，二者不能只看方法名字猜语义。
- `Optional.get()` 会把缺失问题推迟成异常；优先选择 `orElse`、`orElseGet`、`orElseThrow` 或链式转换。
- `Optional` 不替代参数校验、字段建模和集合空值策略；不要为了“看起来函数式”到处嵌套。

## 课后小问

1. 为什么 `Integer a = 128; Integer b = 128; a == b` 不能用来判断数值相等？
答案：包装对象的身份可能来自不同对象，缓存范围也不是业务契约；应使用 `a.equals(b)` 或 `Integer.compare`。
解析：自动装箱把基本值包装成对象，`==` 在两个引用之间比较身份，而不是调用包装类型的数值相等逻辑。

2. 查询方法返回 `Optional<UserId>` 时，调用者该如何处理缺失值？
答案：根据业务选择 `orElse`、`orElseGet` 或 `orElseThrow`，明确默认、延迟计算或异常策略。
解析：`Optional` 的价值是把“可能没有”放到返回类型中，调用者必须作出选择；直接 `get()` 只是把问题推迟成异常。

## 本节小结

- 包装类型适合泛型和可空输入，但自动拆箱、缓存身份和解析异常都有边界。
- `Objects` 提供空值安全比较、哈希和前置校验，值对象要保持 equals/hashCode 一致。
- `Optional` 表达查询缺失，调用方通过默认、异常或映射链明确处理。
- 浮点金额和超范围整数应转到 `BigDecimal`、`BigInteger` 专题，不要依赖隐式类型转换。

## 快速回顾

- 能区分 `parseInt`、`valueOf`、自动装箱和自动拆箱。
- 能用 `Objects.equals`、`hash`、`requireNonNull` 处理常见空值边界。
- 能为 `Optional` 返回选择合理的缺失值处理方式。
- 能判断何时应使用 `BigDecimal` 或检查溢出的 `Math` API。
