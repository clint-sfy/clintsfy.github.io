# Stream 流式处理

## 学习目标

- 区分惰性中间操作与触发计算的终止操作。
- 使用 filter、map、flatMap、sorted、reduce 和 collect。
- 选择 toList、groupingBy、partitioningBy 等收集器并处理空结果。

## 核心知识点

Stream 描述数据处理管道，不负责存储数据；同一个 Stream 只能消费一次。中间操作惰性执行，终止操作才遍历源。优先使用无副作用的 Lambda；`reduce` 需要满足结合律，`collect` 更适合可变归约。并行流依赖拆分器和线程池，不保证顺序，I/O 和小数据量通常不适合并行化。避免在流中修改源集合或调用外部可变状态。

## 实践任务

从订单列表生成报表：过滤已支付订单，按用户分组统计金额，找出 Top 3，并输出不可变结果；分别写串行和并行版本，使用基准数据验证结果一致性和性能。

## 易错点

- 忘记终止操作，导致管道根本不执行。
- 在 peek 中写业务副作用，把调试操作当作逻辑步骤。
- `toMap` 遇到重复键抛异常，没有提供合并函数。
- 并行流中使用非线程安全集合或依赖元素处理顺序。
