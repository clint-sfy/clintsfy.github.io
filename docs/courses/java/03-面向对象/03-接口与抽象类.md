# 接口与抽象类

## 学习目标

- 区分接口、抽象类和普通类的职责。
- 理解 default、static、private 接口方法和多接口冲突解决。
- 设计面向扩展的契约，并编写替代实现测试。

## 核心知识点

接口描述调用者依赖的能力，类可以实现多个接口；抽象类适合共享状态、构造流程和部分实现。接口字段默认是 public static final，抽象方法没有实现；default 方法用于演进 API，但不能堆积业务状态。两个接口出现同签名 default 方法时，实现类必须显式解决冲突。接口隔离原则要求拆小契约，依赖倒置要求高层依赖抽象。

## 实践任务

为报表系统设计 `DataSource`、`Formatter` 和 `Exporter` 三个接口；实现 CSV 与 JSON 导出，使用抽象测试验证所有实现都满足空数据、非法字符和大数据量约束。

## 易错点

- 把接口当作只能有抽象方法的旧式记忆，忽略 default/static 方法。
- 接口类型转换后误调用实现类专有方法，破坏抽象边界。
- 抽象类承担太多职责，子类只能被迫继承无关功能。
- 用 default 方法掩盖不兼容的领域语义。
