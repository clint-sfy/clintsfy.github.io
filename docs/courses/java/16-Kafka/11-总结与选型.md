# 总结与选型

## 一条路径回顾

业务产生事件 → Producer 按 key 选择分区并等待确认 → Broker 追加日志并复制 → Consumer Group 分配分区 → Consumer 处理并提交 offset。任一箭头失败都要分别处理，不能用“消息发出去了”概括全链路。

## 什么时候适合 Kafka

需要多个下游独立读取、较高吞吐、可保留并重放事件、按分区顺序处理时，Kafka 很合适。只需要一个服务同步获得结果，或任务量很小却无法承担集群与消费运维成本时，先选简单方案。
