# 命令行生产消费与消息模型

## 一条消息走过哪里

Producer 选择 Topic 和分区，把记录追加到该分区；Consumer 按分区 offset 读取。相同 key 通常落在同一分区，但增加分区数可能改变之后消息的映射，不能把 key 当作永远稳定的分区号。

## 命令行收发

先执行[快速入门](./03-Kafka快速入门与安装)创建 Topic，再开两个终端：

```bash
bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic learning.events --from-beginning
bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic learning.events
```

在生产者终端输入 `hello` 并回车，消费者会看到 `hello`。`--from-beginning` 读取保留期内的历史消息；使用消费组时还要考虑该组是否已有提交位移。

## 一句话分清几个位置

写入 offset 表示消息在分区日志的位置；当前消费位置表示下一条要取哪里；已提交 offset 是消费组重启后的恢复点。它们不是同一个值。[Kafka Consumer 文档](https://kafka.apache.org/documentation/#consumerapi)。
