# 泛型与类型安全

## 学习目标

- 定义泛型类、接口和泛型方法，减少不必要的强制类型转换。
- 用 `extends`、`super` 和 PECS 设计生产者、消费者参数。
- 理解类型擦除、原始类型、通配符和不可创建泛型数组的限制。

## 核心知识点

### 专业术语

- **类型参数（type parameter）**：如 `<T>` 的类型变量，在编译期约束 API 的输入和输出。
- **通配符（wildcard）**：`?` 表示未知类型，`? extends T` 是有上界的生产者，`? super T` 是有下界的消费者。
- **PECS**：Producer Extends, Consumer Super；读取来源用 `extends`，写入目标用 `super`。
- **类型擦除（type erasure）**：泛型检查主要在编译期完成，运行时通常只保留原始类型边界。
- **堆污染（heap pollution）**：参数化类型引用指向不符合其声明类型对象的状态，常由原始类型或不安全 varargs 引起。

### 白话解释与边界

`List<Integer>` 不是 `List<Number>` 的子类型，因为如果允许这样替换，就能把 `Double` 放进整数列表。`List<? extends Number>` 可以安全读取为 `Number`，但不能添加任意数字；`List<? super Integer>` 可以添加 `Integer`，读取时只能当作 `Object`。类型参数让错误尽量在编译期暴露，但类型擦除意味着运行时不能写 `instanceof List<String>`。

泛型数组不能直接 `new T[]`，因为数组在运行时知道元素类型而泛型通常被擦除，二者规则冲突。优先用 `List<T>` 返回动态结果；若必须使用 varargs 或数组，应把 unchecked 警告压缩在最小、可证明安全的边界。

## 简单案例

```java
import java.util.ArrayList;
import java.util.Collection;
import java.util.List;

public class GenericsDemo {
    static <T> void copy(Iterable<? extends T> source, Collection<? super T> target) {
        for (T value : source) {
            target.add(value);
        }
    }

    static <T extends Comparable<? super T>> T max(List<? extends T> values) {
        T result = values.get(0);
        for (T value : values) {
            if (value.compareTo(result) > 0) {
                result = value;
            }
        }
        return result;
    }

    public static void main(String[] args) {
        List<Integer> numbers = List.of(3, 1, 4);
        List<Number> sink = new ArrayList<>();
        copy(numbers, sink); // numbers 是生产者，sink 是消费者
        System.out.println("sink=" + sink + ", max=" + max(numbers));
    }
}
```

输出为 `sink=[3, 1, 4], max=4`。`copy` 只从 `? extends T` 读取，并向 `? super T` 写入；调用者无需强转，编译器会检查这两个方向是否安全。

## 易混点

- `List<Integer>` 与 `List<Number>` 没有父子关系；泛型通常是不变的，不能按元素继承直觉替换。
- `? extends T` 适合读而不适合添加，`? super T` 适合写入而读取结果只能当 `Object`。
- 类型擦除不等于泛型没有作用，编译期检查仍能阻止大量错误；它只是限制了运行时类型判断。
- `new T[]` 不合法，不能用原始类型或 unchecked 强转随意绕过，否则可能到运行时才暴露堆污染。

## 课后小问

1. 为什么 `copy` 的 source 参数使用 `? extends T`？
答案：source 是生产者，方法只读取其中的 T 或 T 的子类型，因此上界通配符能安全接收更多来源。
解析：方法不会向 source 添加值；若把它写成消费者方向，就会失去接收 `List<Integer>` 等具体列表的能力。

2. 为什么 `List<? super Integer>` 读出来的元素只能视为 `Object`？
答案：实际列表可能是 `List<Integer>`、`List<Number>` 或 `List<Object>`，编译器无法确定更具体的共同类型。
解析：它保证能接受 Integer 写入，但未知的真实类型决定了安全读取上限，只能使用所有引用类型共有的 `Object`。

## 本节小结

- 泛型参数在编译期表达类型关系，减少强转，但通常受类型擦除影响。
- PECS 用 `extends` 表示生产者、`super` 表示消费者，读写方向决定 API 的灵活度。
- 泛型不变性保护了元素安全，通配符用于表达受限的协变或逆变视图。
- 原始类型、泛型数组和不安全 varargs 可能引入堆污染，应缩小警告范围。
