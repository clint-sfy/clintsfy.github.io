# 集合框架与数据结构

## 学习目标

- 区分 `List`、`Set`、`Queue`/`Deque` 和不可变集合的语义。
- 理解 `ArrayList`、`LinkedList`、`ArrayDeque`、`HashSet` 和 `TreeSet` 的取舍。
- 正确迭代、删除、排序，并把复杂度和实际内存开销一起纳入选择。

## 核心知识点

### 专业术语

- **List**：有序、可重复的序列，`ArrayList` 以数组支持快速按索引访问。
- **Set**：强调元素唯一性；`HashSet` 依赖 `equals/hashCode`，`TreeSet` 依赖排序关系。
- **Queue/Deque**：表达先进先出或双端操作，`ArrayDeque` 常用于队列和栈。
- **Iterator**：遍历集合的游标，使用 `Iterator.remove()` 可在遍历中安全删除当前元素。
- **不可变集合**：`List.of`、`Set.of`、`List.copyOf` 返回不能结构性修改的结果视图。

### 白话解释与边界

先说业务语义再选实现：需要按位置访问通常选 `ArrayList`，需要去重选 `Set`，需要首尾进出选 `ArrayDeque`，需要优先级选 `PriorityQueue`。`LinkedList` 的节点插入在已知节点处可以很快，但定位节点仍要遍历，额外节点对象和较差的缓存局部性使它不一定比数组结构快。平均 O(1) 不等于每次都快，扩容、装箱和内存都要考虑。

`List.of` 和 `Set.of` 的结果不可修改且不接受 `null`；`Arrays.asList` 是固定大小的数组视图，允许通过 `set` 替换元素但不能增删。增强 for 中直接结构性修改通常会触发 `ConcurrentModificationException`，应使用迭代器或先收集待删项。

## 常用 API 速查

### `List`：有序、可重复总览

| 任务 | 高频写法 | 说明 |
| --- | --- | --- |
| 创建可变列表 | `new ArrayList<>()`、`new ArrayList<>(source)` | 适合常规增删改；指定初始容量可减少扩容次数。 |
| 创建不可变列表 | `List.of("a", "b")`、`List.copyOf(source)` | 不接受 `null`，不能 `add`/`remove`/`set`。 |
| 创建固定大小视图 | `Arrays.asList("a", "b")` | 允许 `set`，不允许改变大小；底层数组与视图共享元素。 |
| 增加 | `list.add(value)`、`list.add(index, value)` | 后者会移动后续元素；索引必须在 `0..size`。 |
| 读取/修改 | `list.get(index)`、`list.set(index, value)` | `set` 替换元素，不改变列表大小。 |
| 删除 | `list.remove(index)`、`list.remove(value)` | 对 `List<Integer>`，`remove(1)` 是按索引；按值删除写 `remove(Integer.valueOf(1))`。 |
| 查找 | `contains(value)`、`indexOf(value)`、`lastIndexOf(value)` | 依赖元素的 `equals`；找不到索引返回 `-1`。 |
| 遍历 | `for (T value : list)`、`list.forEach(...)` | 需要遍历时删除，用 `Iterator.remove()` 或 `removeIf`。 |
| 排序 | `list.sort(comparator)` | 原地排序；自然顺序用 `Comparator.naturalOrder()`。 |
| 截取 | `list.subList(from, to)` | 左闭右开视图，不是独立副本；需要副本时 `new ArrayList<>(...)`。 |
| 去重保序 | `new ArrayList<>(new LinkedHashSet<>(list))` | 保留首次出现顺序；只需要遍历结果时也可用 `stream().distinct()`。 |

```java
List<String> names = new ArrayList<>(List.of("Bo", "Ann", "Bo"));
names.add("Kai");
names.remove("Bo");
names.sort(Comparator.comparingInt(String::length));
List<String> unique = new ArrayList<>(new LinkedHashSet<>(names));
List<String> part = new ArrayList<>(names.subList(0, Math.min(2, names.size())));
System.out.println("names=" + names + ", unique=" + unique + ", part=" + part);
// 输出：names=[Bo, Ann, Kai], unique=[Bo, Ann, Kai], part=[Bo, Ann]
```

### `ArrayList`/`List.of`/`List.copyOf`：创建 List

常规增删改选 `ArrayList`；`List.of` 和 `List.copyOf` 返回不可变结果且不接受 `null`。示例：`List<String> list = new ArrayList<>(List.of("a", "b"));`。

### `add`/`get`/`set`/`remove`：List 增删改查

`add` 增加、`get` 读取、`set` 替换、`remove` 删除；对 `List<Integer>`，`remove(1)` 按索引，按值删除写 `remove(Integer.valueOf(1))`。示例：`list.add("c"); String first = list.set(0, "A");`（`set` 返回旧值）。

### `contains`/`indexOf`/`lastIndexOf`：List 查找

这些操作依赖元素的 `equals`；`contains` 返回布尔值，索引方法找不到返回 `-1`。示例：`if (list.contains("A")) { int index = list.indexOf("A"); }`。

### 增强 `for`/`forEach`/`Iterator.remove`：遍历与安全删除

只读可用增强 `for` 或 `forEach`，遍历中删除当前元素用迭代器的 `remove`，不要直接调用集合的结构性 `remove`。示例：`for (Iterator<String> it = list.iterator(); it.hasNext();) if (it.next().isBlank()) it.remove();`。

### `List.sort`/`Comparator`：List 排序

`sort` 原地修改列表；自然顺序可用 `Comparator.naturalOrder()`，复杂对象用 `Comparator.comparing`。示例：`list.sort(Comparator.comparingInt(String::length));`。

### `LinkedHashSet`/`stream.distinct`：List 去重

需要保留首次出现顺序时复制到 `LinkedHashSet` 再转回列表；只消费一次结果时可用 `distinct`。示例：`List<String> unique = new ArrayList<>(new LinkedHashSet<>(list));`。

### `subList`：截取 List 视图

区间是左闭右开，返回原列表的视图而不是独立副本；结构性修改原列表可能让视图失效。示例：`List<String> page = new ArrayList<>(list.subList(0, Math.min(10, list.size())));`。

### `Arrays.asList`/`List.of`：区分固定大小与不可变 List

`Arrays.asList` 允许 `set` 但不允许改变大小，`List.of` 连 `set` 也不允许；需要普通可变列表时显式复制。示例：`List<String> fixed = Arrays.asList("a", "b");`。

### `Collections.sort`：旧式 List 排序（低频）

功能可由 `list.sort(comparator)` 替代，老代码或静态工具调用仍会遇到。示例：`Collections.sort(list, Comparator.naturalOrder());`。

### `Collections.unmodifiableList`：只读包装视图（低频）

阻止通过包装引用修改，但底层列表变化仍可能反映出来；需要快照时使用 `List.copyOf`。示例：`List<String> view = Collections.unmodifiableList(list);`。

### `Collections.binarySearch`：有序 List 查找（低频）

要求列表已按相同比较器排序，返回索引或负的插入点编码。示例：`int index = Collections.binarySearch(sorted, "java");`。

### `Set`/`Queue`/`Deque`：类型选择总览

| 类型/实现 | 高频操作 | 选择依据 |
| --- | --- | --- |
| `HashSet` | `add`、`remove`、`contains`、遍历 | 通用去重，平均查找快，但不承诺顺序。 |
| `LinkedHashSet` | 同上 | 去重并保留插入顺序，空间开销略高。 |
| `TreeSet` | `add`、`first`、`last`、`ceiling`、`floor` | 按自然顺序/比较器排序并支持范围附近查找，基本操作通常为 O(log n)。 |
| `Queue`/`ArrayDeque` | `offer`、`poll`、`peek` | FIFO 队列优先使用这组三件套；空队列分别返回 `false`、`null`、`null`。 |
| `Deque`/`ArrayDeque` | `offerFirst/Last`、`pollFirst/Last`、`peekFirst/Last` | 双端进出；作为栈可用 `push`、`pop`、`peek`，不要用 `Stack`。 |
| `PriorityQueue` | `offer`、`poll`、`peek` | 按优先级取出最小/最高优先元素，不保证遍历顺序。 |

```java
Set<String> unique = new LinkedHashSet<>(List.of("a", "b", "a"));
Deque<String> deque = new ArrayDeque<>();
deque.offerLast("task-1");
deque.offerLast("task-2");
String next = deque.pollFirst(); // FIFO 取出 task-1
deque.offerFirst("urgent");
System.out.println("unique=" + unique + ", next=" + next + ", head=" + deque.peekFirst());
// 输出：unique=[a, b], next=task-1, head=urgent
```

### `HashSet.add/remove/contains`：Set 去重与查找

`HashSet` 依赖元素的 `equals`/`hashCode`，适合通用去重和平均 O(1) 查找；不承诺遍历顺序。示例：`Set<String> set = new HashSet<>(); set.add("java"); boolean seen = set.contains("java");`。

### `Set.size/isEmpty/clear`：查看与清空 Set

这些方法与其他集合一致；`clear` 会清空当前集合，不能把它误当成创建新集合。示例：`if (!set.isEmpty()) { int count = set.size(); }`。

### `LinkedHashSet`：去重并保留插入顺序

在哈希去重基础上维护插入顺序，适合去重后仍要稳定展示的场景；空间开销略高。示例：`Set<String> ordered = new LinkedHashSet<>(List.of("b", "a", "b"));`。

### `TreeSet.first/last`：获取排序边界

按自然顺序或比较器维护元素，`first`/`last` 读取最小/最大元素；空集合调用会抛异常。示例：`String min = new TreeSet<>(set).first();`。

### `TreeSet.ceiling/floor`：查找邻近元素

`ceiling` 找大于等于目标的最小元素，`floor` 找小于等于目标的最大元素；找不到返回 `null`。示例：`Integer next = sortedSet.ceiling(10);`。

### `ArrayDeque.offer/poll/peek`：FIFO 队列

优先使用 `offer`、`poll`、`peek` 表达入队、出队、查看队首；容量不足或空队列时分别以返回值表达边界，`ArrayDeque` 不接受 `null`。示例：`queue.offer("job"); String job = queue.poll();`。

### `Queue.add/remove/element`：异常式队列操作（低频）

它们在失败或空队列时抛异常，适合调用方明确要求“必须成功”的场景；一般业务优先使用 `offer`/`poll`/`peek`。示例：`String required = queue.element();`。

### `Deque.offerFirst/offerLast`：双端进出

分别从头尾加入元素，配合 `pollFirst`/`pollLast` 取出；选择哪一端应由业务顺序决定。示例：`deque.offerFirst("urgent"); deque.offerLast("normal");`。

### `Deque.push/pop/peek`：用 Deque 实现栈

`push` 等价于头部压入，`pop` 等价于头部取出，`peek` 查看栈顶；普通栈场景优先 `ArrayDeque`，不要使用遗留 `Stack`。示例：`Deque<String> stack = new ArrayDeque<>(); stack.push("page"); String page = stack.pop();`。

### `PriorityQueue.offer/poll/peek`：优先级队列

按自然顺序或比较器取出优先元素，遍历并不保证排序；默认自然顺序通常先取最小值。示例：`PriorityQueue<Integer> pq = new PriorityQueue<>(); pq.offer(3); int first = pq.poll();`。

### `EnumSet`：枚举集合（低频）

为枚举值提供紧凑的位集合实现，适合状态标记；示例：`EnumSet<Day> workdays = EnumSet.of(Day.MON, Day.FRI);`。

### `BlockingQueue`：生产者消费者队列（低频）

提供阻塞式 `put`/`take` 等操作，适合线程间交接；示例：`BlockingQueue<Task> queue = new ArrayBlockingQueue<>(100);`。

### `ConcurrentLinkedQueue`：非阻塞并发队列（低频）

适合高并发下的无界非阻塞入队出队，不提供阻塞等待；示例：`Queue<Task> queue = new ConcurrentLinkedQueue<>();`。

## 简单案例

```java
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Set;

public class CollectionDemo {
    public static void main(String[] args) {
        List<String> visits = new ArrayList<>(List.of("home", "detail", "home", "pay"));
        Set<String> unique = new LinkedHashSet<>(visits); // 去重且保留首次顺序
        Deque<String> queue = new ArrayDeque<>(unique);
        String first = queue.removeFirst();
        List<String> frozen = List.copyOf(unique);

        System.out.println("first=" + first + ", unique=" + unique);
        // 输出：first=home, unique=[home, detail, pay]
        System.out.println("next=" + queue.peekFirst() + ", frozen=" + frozen);
        // 输出：next=detail, frozen=[home, detail, pay]
    }
}
```

列表保留访问记录，集合负责去重，双端队列按先进先出取出元素，不可变副本则用于防止后续结构性修改；每种容器都承担了清晰的语义。

## 易混点

- `ArrayList` 适合随机访问和尾部追加，`LinkedList` 只有在已有节点位置插入等特定场景有优势，不能凭名字判断更快。
- `List.of` 不可修改，`Arrays.asList` 固定大小，`new ArrayList<>(...)` 才提供常规可变结构。
- 对 `List<Integer>`，`remove(1)` 按索引删除，按值删除要写 `remove(Integer.valueOf(1))`；`subList` 是视图，结构性修改要格外谨慎。
- `HashSet` 的唯一性依赖 equals/hashCode；元素参与哈希的字段变化后，集合可能无法定位它。
- 迭代时调用集合的 `remove` 是结构性修改，使用 `Iterator.remove` 或批量方法才能保持遍历契约。
- 队列优先用 `offer`/`poll`/`peek` 处理容量和空队列边界；`ArrayDeque` 适合普通队列和栈，不接受 `null`。

## 课后小问

1. 需要按索引读取一百万条记录时，为什么通常优先 `ArrayList`？
答案：`ArrayList` 以连续数组支持 O(1) 平均随机访问，节点跳转和额外对象更少。
解析：`LinkedList.get(i)` 需要从头或尾遍历到位置，复杂度和缓存局部性都更差；只有特定节点插入模式才可能占优。

2. 为什么 `Set` 能去重却不能替代所有 `List`？
答案：Set 的契约是唯一性，可能不保留重复项，也不保证调用者需要的顺序或索引位置。
解析：如果展示历史记录必须保留重复和顺序，就应保留 List；去重只是其中一个需求，不能单独决定数据结构。

## 本节小结

- List、Set、Queue/Deque 分别表达序列、唯一集合和排队/双端语义。
- ArrayList 的随机访问和内存局部性通常优于 LinkedList，具体选择仍看操作模式。
- HashSet 依赖相等哈希契约，TreeSet 依赖排序关系，迭代删除要遵守 Iterator 契约。
- `of`/`copyOf` 提供不可变结果，修改需求应显式复制到可变实现。
