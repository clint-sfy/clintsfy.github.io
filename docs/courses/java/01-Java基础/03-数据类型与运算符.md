# 数据类型与运算符

## 学习目标

- 区分八种基本类型与引用类型，知道默认值和 `null` 的边界。
- 能解释装箱拆箱、数值转换、整数溢出和浮点精度问题。
- 使用 `BigDecimal`、字符与 Unicode，以及比较和逻辑运算写出可靠代码。

## 核心知识点

### 专业术语

- **基本类型（primitive type）**：`byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean`，变量直接保存值。
- **引用类型（reference type）**：类、接口、数组和枚举等类型，变量保存对象引用，也可能为 `null`。
- **装箱/拆箱（boxing/unboxing）**：基本类型与 `Integer`、`Long` 等包装对象之间的自动或显式转换。
- **数值提升与窄化转换**：表达式可能先提升为更宽的类型；窄化转换需要显式强转且可能丢失信息。
- **Unicode 码元与字符**：`char` 是一个 UTF-16 code unit，不保证代表一个完整 Unicode 码点。

| 类型 | 位数、范围/默认值（字段） | 字面量与常见用途 |
| --- | --- | --- |
| `byte` | 8 位，-128～127，默认 `0` | `byte b = 12;`；原始字节或紧凑存储 |
| `short` | 16 位，-32,768～32,767，默认 `0` | `short s = 1000;`；明确的紧凑整数 |
| `int` | 32 位，约 ±21 亿，默认 `0` | `int n = 42;`；普通计数和数组下标 |
| `long` | 64 位，约 ±9.22×10¹⁸，默认 `0L` | `long id = 9_000_000_000L;`；时间戳和大 ID |
| `float` | 32 位浮点，约 6～7 位有效数字，默认 `0.0F` | `float f = 1.5F;`；近似测量，通常优先 `double` |
| `double` | 64 位浮点，约 15～16 位有效数字，默认 `0.0D` | `double d = 3.14;`；科学计算和近似小数 |
| `char` | 16 位 UTF-16 码元，0～65,535，默认 `\u0000` | `char c = '中';`；单个码元或字符分类 |
| `boolean` | 逻辑值，默认 `false` | `boolean ok = true;`；开关和条件状态 |

### 白话解释与边界

基本类型适合保存直接数值，引用类型适合表达对象身份；`null` 只能出现在引用类型中，拆箱一个 `null` 包装对象会抛出 `NullPointerException`。整数运算按目标类型宽度进行，溢出会回绕而不是自动报错；需要检查时使用 `Math.addExact`。`double` 是二进制浮点，很多十进制小数无法精确表示，金额和精确小数应改用 `BigDecimal` 的字符串构造器。

表中的默认值只适用于字段和数组元素，局部变量必须先明确赋值。十进制整数默认是 `int`，可用 `0b`、`0x` 和下划线提升可读性，超出 `int` 或明确表达长整数时加 `L`。扩大转换通常保留整数信息，但 `long` 转 `float` 仍可能失去精度；窄化转换必须显式强转，可能截断小数或发生环绕。

`==` 对基本类型比较数值，对引用类型比较是否指向同一对象；对象内容通常使用 `equals`。`&&` 和 `||` 是短路逻辑运算，会按从左到右决定是否执行右侧表达式，因此可用来保护可能为空的访问。

常见运算符可以按意图分组：算术 `+ - * / %` 计算数值，比较 `== != < <= > >=` 产生布尔值，`&&`/`||` 进行短路逻辑，`&`/`|` 可做位运算，条件运算符 `?:` 表达简单二选一。表达式混合多个优先级时应主动加括号，因为可读性比记住完整优先级表更可靠。

位运算还包括 `^`、`~` 和移位 `<<`、`>>`、`>>>`，适合权限掩码或协议字段；`>>` 保留符号位，`>>>` 左侧补零。它们处理的是位模式，不应代替金额或一般业务计算。

| 类别 | 示例 | 边界 |
| --- | --- | --- |
| 算术 | `+ - * / %` | 整数除法截断，整数结果可能溢出，`+` 也可拼接字符串 |
| 比较 | `== != > >= < <=` | 基本类型比值，对象内容通常用 `equals` |
| 逻辑 | `! && ||` | `&&`、`||` 短路；`&`、`|` 不短路 |
| 条件 | `condition ? a : b` | 只适合简单二选一，复杂分支应使用 `if` |

## 简单案例

```java
import java.math.BigDecimal;

public class TypeDemo {
    public static void main(String[] args) {
        Integer boxed = Integer.valueOf(127); // 明确创建包装对象
        int unboxed = boxed;                  // 立即拆箱
        Integer missing = null;
        long widened = unboxed;             // 数值提升
        int binary = 0b1010_0101;
        long visitors = 3_000_000_000L;
        byte left = 100, right = 30;
        int sum = left + right;              // byte 参与算术时提升为 int
        byte wrapped = (byte) (left + right); // 130 窄化后回绕为 -126
        int overflow = Integer.MAX_VALUE + 1;
        int wrappedSum = Math.addExact(40, 2);
        BigDecimal money = new BigDecimal("0.10").add(new BigDecimal("0.20"));
        String emoji = "🙂";

        int permissions = 0b0101;
        int write = 0b0010;
        boolean canWrite = (permissions & write) != 0;
        int signedShift = -8 >> 1;
        int unsignedShift = -8 >>> 1;
        System.out.println("sum=" + wrappedSum + ", long=" + widened + ", binary=" + binary);
        System.out.println("byteSum=" + sum + ", narrowed=" + wrapped + ", overflow=" + overflow
                + ", visitors=" + visitors + ", canWrite=" + canWrite
                + ", signedShift=" + signedShift + ", unsignedShift=" + unsignedShift);
        System.out.println("money=" + money + ", chars=" + emoji.length()
                + ", codePoints=" + emoji.codePointCount(0, emoji.length()));
        System.out.println("safe=" + (missing == null || missing > 0));
    }
}
```

输出会包含 `money=0.30`、`chars=2` 和 `codePoints=1`。表情的一个 Unicode 码点在 UTF-16 中占两个 `char`，所以 `length()` 不是用户可见字符数；`missing == null || ...` 也因短路而不会拆箱空值。

## 易混点

- `Integer` 是对象而 `int` 是值；自动拆箱方便但可能因 `null` 抛异常，不能把两者边界隐藏起来。
- `==` 比较引用身份，`equals` 比较内容（前提是类型正确重写）；字符串和包装对象不要依赖缓存对象的身份。
- 强制转换只改变表达式的目标类型，不会修复溢出或恢复已经丢失的小数精度。
- `char` 表示 UTF-16 码元，码点数量和用户看到的字素簇都可能与 `length()` 不同。

## 课后小问

1. 为什么 `new BigDecimal(0.1)` 不推荐用于金额？
答案：`0.1` 先以二进制 `double` 近似值存在，再被转换进 `BigDecimal`，误差会被保留下来。
解析：用字符串 `new BigDecimal("0.1")` 直接表达十进制意图，并在除法等操作中明确舍入规则，结果才可审计。

2. `==` 比较两个 `Integer` 时，为什么结果可能与预期不同？
答案：引用类型的 `==` 比较对象身份，缓存范围内外可能引用不同对象；内容比较应使用 `equals`。
解析：自动装箱不保证每次返回同一个对象，依赖身份比较会把实现细节当成业务规则，因此应明确拆箱或调用 `equals`。

## 本节小结

- 基本类型保存值，引用类型保存对象引用，`null` 只属于引用类型。
- 装箱拆箱提升了可用性，却带来缓存身份、额外对象和空值拆箱边界。
- 整数会溢出回绕，浮点数有表示误差；精确金额应使用字符串构造的 `BigDecimal`。
- 比较、短路逻辑和 Unicode 的单位必须与业务语义匹配。
