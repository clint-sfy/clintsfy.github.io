# 控制流与方法

## 学习目标

- 使用 `if`、传统 `switch`、`switch` 表达式和循环表达分支与重复。
- 用早返回、输入校验和清晰的方法职责降低嵌套复杂度。
- 理解重载、可变参数、递归和局部变量作用域的运行边界。

## 核心知识点

### 专业术语

- **控制流（control flow）**：决定语句执行顺序的分支、循环、跳转和方法调用。
- **switch 表达式**：产生值的 `switch`，可用 `case` 箭头和 `yield`，是 JDK 14 起的正式特性。
- **早返回（guard clause）**：先处理无效或特殊输入并立即返回，让主路径保持平坦。
- **重载（overload）**：同一作用域中方法名相同但参数列表不同；选择发生在编译期。
- **可变参数（varargs）**：`T...` 在调用处表现为数组，方法内仍需面对空数组和 `null` 数组。

### 白话解释与边界

`if` 适合布尔条件，传统 `switch` 适合执行语句，`switch` 表达式适合把一个分类直接转成值；三者都不会自动校验业务输入。循环要保证初始化、条件和更新共同推动终止，否则会无限循环。早返回不是忽略错误，而是把边界条件集中在入口，让剩余代码只处理合法状态。

方法应围绕一个可命名的职责，参数校验应尽早完成。递归必须有明确的基线条件，并注意调用栈深度；大量数据通常改用循环。`switch` 的模式匹配仍属于另一个预览主题，本节只讨论 JDK 20 中已正式可用的常量、字符串和枚举分支。

| 结构 | 适合表达的语义 | 需要留意的边界 |
| --- | --- | --- |
| `if/else` | 范围判断、组合条件和早返回 | 条件过多时应提取命名方法，避免深层嵌套 |
| 传统 `switch` | 固定标签下执行多条语句 | 冒号分支可能穿透，需用 `break` 或明确利用穿透 |
| `switch` 表达式 | 把分类直接产生一个值 | 所有路径必须产值，复杂分支用代码块和 `yield` |
| `for`/`while`/`do-while` | 已知次数、先判断或至少执行一次的循环 | 初始化、条件和更新必须共同保证终止 |

方法职责也应分层：入口方法负责取得和校验输入，纯计算方法负责返回结果，展示方法负责输出。这样重载只表达参数形式差异，递归和循环的边界也能分别测试，而不会让一个方法同时承担输入、业务和 I/O。

## 简单案例

```java
public class FlowDemo {
    static String level(int score) {
        if (score < 0 || score > 100) { // 入口校验，早失败
            throw new IllegalArgumentException("score out of range");
        }
        return switch (score / 10) {
            case 10, 9 -> "A";
            case 8 -> "B";
            case 7 -> "C";
            default -> "D";
        };
    }

    static String dayType(int day) { // 传统 switch：冒号分支配合 break/return
        String result;
        switch (day) {
            case 1:
            case 7:
                result = "weekend";
                break;
            case 2:
            case 3:
            case 4:
            case 5:
            case 6:
                result = "weekday";
                break;
            default:
                throw new IllegalArgumentException("day out of range");
        }
        return result;
    }

    static int sumUntilZero(int... values) {
        int total = 0;
        for (int value : values) {
            if (value < 0) continue; // continue 跳过本轮
            if (value == 0) break;   // break 结束循环
            total += value;
        }
        return total;
    }

    static int loopSummary() {
        int retry = 0;
        while (retry < 2) retry++;
        int shown = 0;
        do {
            shown++;
        } while (shown < 1);
        return retry + shown;
    }

    static String format(int value) { return "int:" + value; }
    static String format(String value) { return "text:" + value; }

    static int factorial(int n) {
        if (n < 0) {
            throw new IllegalArgumentException("n must be non-negative");
        }
        return n <= 1 ? 1 : n * factorial(n - 1);
    }

    public static void main(String[] args) {
        System.out.println(level(86) + ", " + dayType(7));
        System.out.println("sum=" + sumUntilZero(1, -2, 3, 0, 100)
                + ", loops=" + loopSummary());
        System.out.println(format(4) + ", " + format("ok") + ", factorial=" + factorial(4));
    }
}
```

输出为 `B, weekend`、`sum=4, loops=3` 和 `int:4, text:ok, factorial=24`。`level` 先做输入校验再用正式的 `switch` 表达式产值；`dayType` 展示传统语句，`sumUntilZero` 展示 `continue` 与 `break`，`loopSummary` 展示 `while` 与至少执行一次的 `do-while`。`format` 的选择按编译期参数列表完成，递归的 `n <= 1` 是终止条件。

## 易混点

- `switch` 语句靠 `break` 控制穿透，`switch` 表达式用箭头或 `yield` 产值；两者不是同一套写法。
- JDK 20 的常量/枚举 `switch` 表达式已正式可用，类型模式匹配仍要按预览命令编译，不能混为一谈。
- 可变参数不是无限参数，调用者仍可能传入空数组或显式 `null`，方法必须定义其含义。
- 递归适合能自然分解且深度可控的问题；输入规模不可控时循环更能避免栈溢出。

## 课后小问

1. 为什么 `switch` 表达式需要覆盖所有可能分支？
答案：表达式必须产生一个值，编译器需要确认每条控制路径都有结果，因此通常要写 `default` 或覆盖完整枚举值。
解析：传统 `switch` 可以执行完而不赋值；表达式若遗漏分支会留下未定义结果，编译器会拒绝这种不完整写法。

2. `sumUntilZero()` 和 `sumUntilZero((int[]) null)` 的输入边界一样吗？
答案：不一样；前者得到长度为零的数组并返回 0，后者把 `null` 数组传入增强 `for`，当前实现会抛出 `NullPointerException`。
解析：可变参数只是数组语法糖，空数组和 `null` 是两个不同状态；该实现没有先判空，因此空数组能正常遍历，而 `null` 在进入循环时就失败。若业务要接受 `null`，应在方法入口增加明确的校验或默认策略。

## 本节小结

- 条件、循环和方法调用共同构成控制流，输入校验应靠近方法入口。
- `switch` 表达式产生值，JDK 20 已正式支持但模式匹配仍需单独识别预览状态。
- 早返回能突出主路径，方法职责应可命名且边界清楚。
- 可变参数是数组，递归必须有基线条件和可控深度。
