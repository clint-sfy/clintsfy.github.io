# 反射与注解

## 学习目标

- 通过 Class、Constructor、Method、Field 读取类型元数据。
- 定义 SOURCE、CLASS、RUNTIME 不同保留策略的注解。
- 评估反射的可见性、模块边界、性能和安全影响。

## 核心知识点

`Class.forName`、类字面量和对象 `getClass` 可获取类型；反射调用需要处理参数类型、异常和访问权限。注解由 `@Target`、`@Retention`、`@Documented` 等元注解描述；RUNTIME 注解才能通过 `getAnnotation` 读取。反射适合框架注册、序列化和测试工具，不应替代正常多态。缓存 Method/Field、限制可访问范围，并在模块化环境配置 opens。

## 实践任务

定义 `@Command(name)` 注解，扫描一个受控包中的命令类并生成路由表；校验重复名称、参数签名和访问权限，写测试覆盖缺失注解和调用异常。

## 易错点

- 忘记设置 RUNTIME，运行时读取不到注解。
- 依赖 setAccessible 绕过封装，在强模块边界下失败。
- 反射调用吞掉 InvocationTargetException 的根因。
- 扫描整个 classpath，导致启动慢、类初始化副作用和安全风险。
