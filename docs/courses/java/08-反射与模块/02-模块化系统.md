# 模块化系统

## 学习目标

- 读写 module-info.java 中的 requires、exports、opens 和 provides。
- 区分类路径与模块路径，理解可读性和强封装。
- 使用 jdeps、jlink 检查依赖并构建精简运行时。

## 核心知识点

模块通过 `module-info.java` 声明名称、依赖和导出包；`requires transitive` 会把可读性传递给下游，`exports` 只暴露编译/运行 API，`opens` 为反射开放运行时访问。服务加载使用 `uses/provides ... with`。未命名模块和自动模块用于迁移旧 classpath 应用。模块化不是简单改目录，需检查 split package、循环依赖和第三方库兼容。

## 实践任务

把一个命令行应用拆成 api、core、cli 三个模块：只导出 api 包，用 provides/uses 注入实现；用 jdeps 找出依赖，再用 jlink 构建最小运行时并运行 smoke test。

## 易错点

- 只写 requires 忘记 exports，导致外部无法访问公共类型。
- 误把 opens 当作 exports，破坏 API 封装。
- 在模块路径和类路径混用时出现重复类或自动模块名称冲突。
- 反射框架没有为目标包配置 opens。

## 复习清单

- [ ] 能区分 requires、exports、opens、uses、provides。
- [ ] 能定位类路径/模块路径下的可读性问题。
- [ ] 能为第三方库迁移说明自动模块风险。
