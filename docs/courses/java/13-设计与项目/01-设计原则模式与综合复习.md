# 设计原则、常见模式与综合复习

## 学习目标

- 用单一职责、开闭、里氏替换、接口隔离、依赖倒置审查设计。
- 识别策略、工厂、建造者、装饰器、观察者、模板方法和适配器模式。
- 把语言、集合、并发、JVM、测试和数据库知识整合到一个项目。
- 建立从需求、实现、测试、观测、性能到复盘的进阶学习路线。

## 核心知识点

模式是重复出现的协作结构，不是类名清单；先识别变化点和约束，再选择策略或工厂等模式。综合项目可做“订单/库存服务”：用 record 表示命令和结果，用接口隔离支付策略，用集合维护内存索引，用 Stream 生成报表，用 JDBC 持久化，用 Maven/JUnit/日志形成工程闭环，用 Executor 或虚拟线程处理异步任务，再通过 JFR 和 GC 日志验证性能。复习顺序建议为：语法与对象 → 异常/泛型/集合 → Lambda/Stream/IO → 反射/模块 → 并发/JMM → JVM → 工程化；每阶段结合可运行的例子理解概念和适用边界。

## 一个完整的结算例子

策略模式把变化的折扣规则交给接口实现，结算代码只关心输入和结果。下面保存为 `CheckoutDemo.java`，用 `javac CheckoutDemo.java` 编译，再用 `java CheckoutDemo` 运行。

```java
public class CheckoutDemo {
    interface Discount { int apply(int cents); }

    static int checkout(int cents, Discount discount) {
        return discount.apply(cents);
    }

    public static void main(String[] args) {
        Discount vip = cents -> cents * 80 / 100;
        System.out.println(checkout(1000, vip)); // 800
    }
}
```

原价为 1000 分，VIP 策略返回 800 分。替换 `vip` 即可更换规则，而不用修改 `checkout`。当规则只有一个且不会变化时，直接计算可能更简单。真实金额运算还应明确舍入方式和边界。

## 如何选择模式

策略用于替换算法，工厂用于集中创建对象，装饰器用于在保持接口的同时叠加行为。它们解决的问题不同，也可以组合使用：工厂选择折扣策略，装饰器为策略增加计时。先识别变化点，再决定是否需要抽象；详细例子见本章后续文章。

## 易错点

- 为了套模式而套模式，抽象层级超过真实变化点。
- 只测 happy path，不测重试、并发、超时、回滚和资源关闭。
- 把“能运行”当作“可维护”，没有边界、日志、指标和文档。
- 只背 JVM 参数或 API，不用可复现实验验证假设。
