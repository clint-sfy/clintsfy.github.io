# 装饰器、适配器与建造者

装饰器给已有能力叠加行为；适配器转换不兼容的接口；建造者组织复杂对象的构造。下面每个代码块都可以在 JDK 17+ 的 JShell 新会话中独立运行。

## 先判断需要改变什么

调用方已经认识 `Sender`，只是需要额外记录发送行为时，装饰器可以接收原对象并继续实现同一接口。调用一次装饰器会先执行附加行为，再委托原对象；遗漏委托就会改变原有功能。多层包装的执行顺序由构造顺序决定。

旧短信库只有 `deliver` 而业务要求 `send` 时，适配器翻译调用方式。适配器也要明确失败语义：旧库返回失败码时，不能假装消息发送成功。建造者处理的则是创建阶段的参数组织；它不会自动解决发送过程的异常或重试。

## 结构与构造

### 装饰器模式：包装并增强同一接口

包装对象和被包装对象实现同一接口，因此调用方仍使用 `send`，而包装层可以追加日志。

```java
interface Sender { void send(String message); }
class LoggingSender implements Sender {
    private final Sender delegate;
    LoggingSender(Sender delegate) { this.delegate = delegate; }
    public void send(String message) {
        System.out.println("准备发送");
        delegate.send(message);
    }
}
Sender sender = new LoggingSender(System.out::println);
sender.send("订单已创建");
```

适合按需组合日志、计时等行为。包装顺序会影响结果；生产日志还要避免泄露敏感信息，委托失败时也要明确异常是否继续传播。

### 适配器模式：转换不兼容接口

旧系统提供 `deliver`，新业务需要 `send`；适配器负责把一种调用翻译成另一种调用。

```java
interface Sender { void send(String message); }
class LegacySms {
    void deliver(String text) { System.out.println("短信: " + text); }
}
class SmsAdapter implements Sender {
    private final LegacySms sms = new LegacySms();
    public void send(String message) { sms.deliver(message); }
}
Sender sender = new SmsAdapter();
sender.send("验证码"); // 短信: 验证码
```

适配器解决接口不匹配，而非自动保证语义一致：实际接入时还要映射错误、编码和超时。装饰器保持原接口并增加行为，适配器则面向不同接口转换。

### 建造者模式：分步构造并校验

多个可选配置容易使构造函数参数难以辨认；建造者用具名方法设置选项，`build` 创建最终对象。

```java
class RequestOptions {
    final int timeoutMillis;
    final int retries;
    private RequestOptions(Builder b) {
        timeoutMillis = b.timeoutMillis;
        retries = b.retries;
    }
    static class Builder {
        private int timeoutMillis = 1000;
        private int retries = 0;
        Builder timeoutMillis(int value) { timeoutMillis = value; return this; }
        Builder retries(int value) { retries = value; return this; }
        RequestOptions build() {
            if (timeoutMillis <= 0 || retries < 0) throw new IllegalArgumentException();
            return new RequestOptions(this);
        }
    }
}
var options = new RequestOptions.Builder().timeoutMillis(2000).retries(2).build();
System.out.println(options.timeoutMillis); // 2000
```

`build` 是校验最终组合的边界；对象字段声明为 `final` 可避免构造后修改。只有一两个必填参数时，普通构造器或 record 往往更清晰。

## 易混点

装饰器保留同一接口并叠加行为，适配器把旧接口转换为调用方需要的接口，建造者负责构造对象。包装多个装饰器时顺序会改变日志、计时或异常处理的观察结果。
