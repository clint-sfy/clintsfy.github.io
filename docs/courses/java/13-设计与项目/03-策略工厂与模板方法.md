# 策略、工厂与模板方法

当变化发生在算法、对象选择或流程中的某一步时，这三种模式分别提供不同的组织方式。下列代码块可分别在 JDK 17+ 的 JShell 新会话运行。

## 行为和创建

### 策略模式：替换算法

策略把折扣计算封装为可替换的行为；调用方传入价格（分）并得到折后价格。

```java
interface Discount { int apply(int cents); }
class Checkout {
    private final Discount discount;
    Checkout(Discount discount) { this.discount = discount; }
    int total(int cents) { return discount.apply(cents); }
}
Discount vip = cents -> cents * 8 / 10;
System.out.println(new Checkout(vip).total(1000));
// 输出：800
```

适合规则有多种且会变化的场景。策略由谁选择是另一个问题；折扣输入范围和舍入也必须在真实业务中约定。

### 简单工厂：集中选择实现

工厂集中处理输入到策略的映射，避免每个调用方重复写选择逻辑。

```java
interface Discount { int apply(int cents); }
class Discounts {
    static Discount forLevel(String level) {
        return switch (level) {
            case "VIP" -> cents -> cents * 8 / 10;
            case "NORMAL" -> cents -> cents;
            default -> throw new IllegalArgumentException("未知等级: " + level);
        };
    }
}
System.out.println(Discounts.forLevel("VIP").apply(1000));
// 输出：800
```

未知等级在这里显式报错，避免静默给错价格；`null` 也不是有效等级，调用边界应先校验。新增等级仍须修改这个工厂，因此它是简单工厂，不等同于通过子类扩展创建步骤的工厂方法模式。

### 工厂方法模式：让创建步骤可替换

工厂方法让公共流程调用可重写的创建方法；不同子类负责提供不同的产品。

```java
interface Exporter { String export(String data); }
abstract class ExportJob {
    protected abstract Exporter createExporter();
    String run(String data) { return createExporter().export(data); }
}
class TextJob extends ExportJob {
    protected Exporter createExporter() { return data -> "TEXT: " + data; }
}
System.out.println(new TextJob().run("订单"));
// 输出：TEXT: 订单
```

适合创建过程与公共流程一起复用且产品确实有变体；只有少量固定类型时，简单工厂可能更直接。

### 模板方法模式：固定流程并替换步骤

模板方法把步骤顺序放在父类中，让子类实现变化的步骤；`final` 防止子类改变流程顺序。

```java
abstract class ImportJob {
    final void run(String input) {
        String clean = input.trim();
        if (clean.isEmpty()) throw new IllegalArgumentException("内容为空");
        save(clean);
    }
    protected abstract void save(String value);
}
class ConsoleImport extends ImportJob {
    protected void save(String value) { System.out.println("保存: " + value); }
}
new ConsoleImport().run("  order-1  ");
// 输出：保存: order-1
```

模板方法依赖继承，父类修改步骤可能影响所有子类；如果步骤需要运行时自由组合，可以考虑用组合和策略。真实导入还需定义失败、事务和重复数据处理。

## 易混点

策略替换算法，工厂负责选择或创建对象，模板方法固定流程的步骤顺序。简单工厂里的 `switch` 集中选择实现，但新增分支仍需修改工厂；工厂方法则通过重写创建方法扩展产品。
