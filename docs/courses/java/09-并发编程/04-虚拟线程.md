# 虚拟线程

## 学习目标

- 区分平台线程与虚拟线程的成本、调度和生命周期。
- 使用 Thread.ofVirtual、Executors.newVirtualThreadPerTaskExecutor。
- 识别 pinning、线程本地变量和资源连接池带来的限制。

## 核心知识点

虚拟线程由 JVM 调度到少量载体平台线程上，适合大量主要等待 I/O 的短任务，不等于让 CPU 计算无限并行。阻塞式 Java I/O 通常会挂起虚拟线程而释放载体；在 synchronized 监视器或 native 调用中可能 pin 住载体，需用 JFR/诊断工具验证。虚拟线程数量低成本，不代表数据库连接、文件句柄等外部资源无限。每任务一个虚拟线程执行器仍需显式关闭。

## 实践任务

实现并发抓取器：每个 URL 一个虚拟线程，限制连接并发，设置超时并汇总结果；与固定平台线程池比较吞吐、内存和尾延迟，记录测试负载。

## 易错点

- 用虚拟线程执行长时间 CPU 密集循环，造成载体饥饿。
- 创建无限数据库连接，误把线程扩展性当作下游扩展性。
- 在大 synchronized 临界区执行阻塞调用导致 pinning。
- 忘记取消和关闭任务，应用退出时仍有未完成工作。
