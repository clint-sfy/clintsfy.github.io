# 异常体系与资源管理

## 学习目标

- 区分 Error、RuntimeException 和受检异常，设计稳定的错误边界。
- 使用 try-catch-finally、try-with-resources 和自定义异常。
- 保留根因、上下文和可观测信息，避免吞异常。

## 核心知识点

`Throwable` 下有 `Error` 和 `Exception`；业务可恢复错误通常建模为异常或结果类型。受检异常迫使调用者处理，运行时异常多表示编程错误或非法状态。捕获应从具体到一般，重新抛出时使用 `new XException(message, cause)` 保留异常链。实现 `AutoCloseable` 的资源可由 try-with-resources 自动关闭，多个资源按声明逆序关闭，关闭异常会成为 suppressed exception。finally 不应覆盖原异常。

## 实践任务

实现文件导入服务：将编码、格式、校验、持久化异常分层映射；使用自定义 `ImportException` 保存文件名和行号，try-with-resources 读取文件，并为关闭失败编写测试。

## 易错点

- `catch (Exception) {}` 吞掉错误，使调用者无法恢复或告警。
- 先捕获父类再捕获子类，造成编译错误或错误分类。
- 在 finally 中 return，覆盖 try/catch 的返回值和异常。
- 只记录异常消息，不记录 stack trace、请求 ID 和根因。
