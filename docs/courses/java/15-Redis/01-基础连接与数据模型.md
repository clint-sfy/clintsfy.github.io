# 基础连接与数据模型

## 学习目标

掌握本篇独立命令的输入、返回与状态变化，按访问形状选择结构，并为键、返回数量和失败重试设置边界。

## 核心知识点

本篇采用 Redis 8 稳定主版本的基础命令语义；官方文档核对日期：2026-10-06，不声明未验证的补丁版本。[官方数据类型](https://redis.io/docs/latest/develop/data-types/) 是本章事实依据。

Redis 是网络数据结构服务器；key 和 String value 都是二进制安全的字节序列，Hash/List 等值有专用命令。key 使用业务前缀和版本，例如 lab:{core}:name；花括号内的 hash tag 让本章多键实验落在同一 Cluster 槽，但生产环境不能把全部业务集中到一个槽。内存、过期、淘汰、复制和持久化共同决定数据寿命，Redis 不能自动提供与数据库的跨资源事务。

实验前提：本机独立 Redis 8 服务在 127.0.0.1:6379 运行；通过终端执行 `redis-cli -h 127.0.0.1 -p 6379` 后在交互提示符输入下面的命令（不是 PowerShell 命令）。有 ACL 时用 `--user lab_user --askpass` 输入密码。示例注释记录返回，不需要把输出复制成输入；不同客户端的数组排版可能不同。

连接例不改变业务数据；TYPE/EXISTS 例开始前执行 `DEL lab:{core}:name lab:{core}:missing` 清理指定实验键，结束后再次执行同样清理。不要在业务环境运行学习写入。

## 常用用法

### `PING`：检查当前连接能否与服务端交互

用于检查当前连接能否与服务端交互。

```redis
# 初始：本机 127.0.0.1:6379 实验连接已建立，name 和 missing 键不存在。
PING
# 关键变化：读取连接响应，PONG 表明服务收到请求。
# 输出：PONG。
```

连接可达不等于拥有业务命令权限，也不保证复制节点的数据最新。 官方参考：[PING](https://redis.io/docs/latest/commands/ping/)。

### `AUTH`：验证学习账号并确认认证后的命令权限

用于验证学习账号并确认认证后的命令权限。

```redis
# 初始：本机实验 ACL 已配置 lab_user，当前连接尚未认证。
AUTH lab_user "lab-only-password"
PING
# 关键变化：连接身份变为 lab_user。
# 输出：AUTH 为 OK，PING 为 PONG。
```

仅在独立本机实验服务预先配置 ACL 用户 lab_user 和此演示密码；生产密码不写到历史、脚本或日志。正常连接优先用 redis-cli --user lab_user --askpass，在 TLS 环境启用 --tls 并验证证书；ACL 还需限制 key 范围和命令。 官方参考：[AUTH](https://redis.io/docs/latest/commands/auth/)。

### `SELECT`：切换独立连接的逻辑数据库以理解命名空间

用于切换独立连接的逻辑数据库以理解命名空间。

```redis
# 初始：standalone 当前连接使用数据库 0，至少配置两个数据库。
SELECT 1
SELECT 0
# 关键变化：当前数据库先变为 1，再恢复为 0。
# 输出：两次均为 OK，最终回到数据库 0。
```

本例仅适用于配置了至少两个数据库的 standalone；Redis Cluster 仅支持数据库 0，禁止依赖 SELECT 隔离租户。逻辑数据库共享服务资源。 官方参考：[SELECT](https://redis.io/docs/latest/commands/select/)。

### `TYPE`：识别值的数据结构以选择匹配的操作命令

用于识别值的数据结构以选择匹配的操作命令。

```redis
# 初始：本机 127.0.0.1:6379 实验连接已建立，name 和 missing 键不存在。
SET lab:{core}:name Ann
TYPE lab:{core}:name
# 关键变化：name 写入 Ann，TYPE 读取其 String 类型。
# 输出：SET 为 OK，TYPE 为 string。
```

对 String 执行 HGET 会产生 WRONGTYPE；缺失 key 的 TYPE 是 none。清理：DEL lab:{core}:name。 官方参考：[TYPE](https://redis.io/docs/latest/commands/type/)。

### `EXISTS`：检查明确的键是否存在并解释返回的计数

用于检查明确的键是否存在并解释返回的计数。

```redis
# 初始：本机 127.0.0.1:6379 实验连接已建立，name 和 missing 键不存在。
SET lab:{core}:name Ann
EXISTS lab:{core}:name lab:{core}:missing
# 关键变化：name 被创建，missing 仍不存在，因此存在计数为 1。
# 输出：SET 为 OK，EXISTS 为整数 1。
```

先确保 missing 不存在；重复传入同一现有 key 会重复计数。检查后再写有竞争窗口，条件写应使用 SET NX。清理：DEL lab:{core}:name。 官方参考：[EXISTS](https://redis.io/docs/latest/commands/exists/)。

## 易混点

命令返回的整数有的表示数量、有的表示旧值或新值，应按命令解释；nil 与空字符串不同。单命令原子不等于跨命令或跨数据库的业务事务。

## 课后小问

1. 本篇怎样验证示例没有依赖上一次实验？

答案：每个小节先清理明确实验 key，再按本段重建输入，读回结果后清理；连接与认证例按注明的连接前置条件执行。

2. 网络超时后能否直接重试写操作？

答案：不能由超时推断服务端未执行。对计数、入队、事件追加等写操作应设计幂等、重试上限与恢复路径。

## 本节小结

按输入与输出验证命令语义，再评估数据量、阻塞时间、精度和失败路径；实验清理只针对明确学习 key。
