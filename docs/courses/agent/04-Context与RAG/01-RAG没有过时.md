# RAG 没有过时，只是升级了

RAG 仍然是把私有、实时或可追溯知识交给模型的重要方式。过时的是“切块后全部塞进向量库，只取 top-k 就结束”的单一路线。

## 现代 RAG 更关注

- 根据问题选择关键词、向量、图谱或数据库查询；
- metadata 过滤、权限过滤和时间范围；
- query rewrite、混合检索与 rerank；
- 为答案保留来源和可验证引用；
- 对召回率、精确率、答案忠实度分别评测；
- 控制上下文预算，避免检索结果挤掉关键指令；
- 在检索失败时明确降级，而不是让模型编造。

长上下文模型减少了一部分简单检索需求，但没有消除数据新鲜度、权限、成本和证据追踪问题。RAG 应当放进更大的 Context Engineering 体系里学习。
