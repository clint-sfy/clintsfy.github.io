# Agent 系统组成

一个可用的 Agent 不是“模型加一段很长的提示词”，而是一个持续执行的闭环：

1. 接收目标和当前状态；
2. 判断下一步是回答、调用工具还是继续收集信息；
3. 执行动作并读取真实结果；
4. 更新上下文与任务状态；
5. 在完成、失败或需要用户决策时停止。

## 最小组成

- **Model**：负责理解、推理与决策。
- **Instructions**：定义角色、边界、完成标准和安全规则。
- **Tools**：让模型读取或改变外部世界。
- **State**：保存任务进度、会话数据和可恢复信息。
- **Context**：在当前一步真正提供给模型的信息。
- **Guardrails**：权限、输入输出校验、人工确认和资源限制。
- **Evals / Tracing**：判断系统是否稳定完成任务，并能定位失败原因。

学习时先实现一个工具很少、状态明确的单 Agent，再考虑多 Agent。多 Agent 解决的是并行、专业分工和上下文隔离，不是让系统自动变聪明。
