# Java 后端学习路线顺序化设计规范

状态：已批准，作为后续课程重排、扩写和验收的单一范围依据。

## 1. 目标与现状

现有课程已经覆盖 Java 语言、标准库、并发、JVM 和部分后端工程，但 MySQL 与 Redis 仅各有一篇速查，且 MySQL 位于 MyBatis 之后，不适合按顺序学习。本次把课程整理成“语言与标准库 → 运行时 → 数据库 → 工程工具 → 设计 → Spring 后端 → Redis”的依赖顺序，并把 MySQL 8 与 Redis 扩写为可以独立学习、也可以按标题速查的完整章节。

若依源码只用于建立最低覆盖基线：源码实际调用到的外部 API 必须能在笔记中查到，但课程范围不由若依限定。Java 官方常用 API、MySQL 8 常用能力、Redis 官方常用命令以及通用生产实践同样必须覆盖。

现状审计基线为 94 篇课程文章、13 个章节；现有测试保存了 159 个外部 API 精确标题门槛。此前源码扫描得到 379 个外部符号，高频 43/43、中频 84/84 已有归属。这些数字只描述迁移前基线，重排后必须重新扫描和分类，不能直接沿用为新路线的完成证明。

## 2. 固定技术基线

- Java 示例统一使用 JDK 20；预览或孵化能力必须标注 JDK 20 状态和所需编译、运行参数。
- 数据库统一使用 MySQL 8.0 与 InnoDB，不混入其他数据库方言。
- ORM 以 MyBatis-Plus 为主要实践入口，同时讲清原生 MyBatis 的映射、动态 SQL、缓存和插件边界。
- Redis 以实施时当前稳定官方文档为事实依据，文章注明适用的大版本与能力边界，不绑定短生命周期补丁版本，也不把候选版能力写成稳定能力。
- 站点继续使用现有 VitePress 静态构建与 GitHub Pages 部署，不增加服务端依赖。

## 6. 单一事实源与知识边界

为避免重复和相互矛盾，同一知识只在一个章节完整解释，其他章节链接引用：

- **MySQL 8**：SQL 语义、数据类型、索引、执行计划、InnoDB 事务/MVCC/锁、账号与备份的单一事实源。
- **JDBC（工程实践）**：Java 数据库接口、连接生命周期、PreparedStatement、ResultSet、事务 API 与连接池使用边界；不重复数据库内部原理。
- **MyBatis/MyBatis-Plus（Spring 后端工程）**：对象映射、Mapper、动态 SQL、分页、批处理、插件、缓存和 ORM 生产边界；不重新教授 SQL 基础。
- **Spring 事务（Spring 后端工程）**：代理、传播、回滚规则、事务同步和跨资源边界；数据库隔离与锁链接到 MySQL 8。
- **Redis Core（Redis）**：命令语义、数据结构、过期、持久化、复制、集群和服务端诊断的单一事实源。
- **Spring Data Redis（Redis）**：客户端模板、序列化、连接、缓存注解及 Java 异常处理；命令行为链接到 Redis Core。

同一 API 可以在调用场景中再次出现，但必须链接事实源，且不得给出不同版本、默认值或安全结论。

## 8. 文章统一结构

所有新增和迁移后文章统一使用：

1. frontmatter：`title`、`date`、`category`、`tags`、`description`。
2. `# 标题`、`## 学习目标`。
3. `## 核心知识点`：先给专业术语，再用白话解释用途、前提和边界。
4. `## 常用用法`：每个独立 API、命令或操作使用单独的 `###` 小标题，标题必须含可搜索的真实名称。
5. 每个小标题后先用一句话说明“用于什么、什么时候用”，再给最小可运行或可执行案例。
6. 案例注释必须明确具体输入/初始状态、每个关键步骤后的状态变化、最终输出或可观察结果；禁止只留一条输出注释，也禁止“执行后得到预期结果”之类模板话术。
7. `## 易混点`、`## 课后小问`（含答案与解析）、`## 本节小结`、`## 快速回顾`。

SQL/Redis CLI 示例不强行包装成 Java 类；Java API 示例使用 JDK 20 可编译代码。无确定输出的网络、并发或框架案例要写可观察状态、日志或断言，不伪造确定结果。

GitHub Pages 无服务端 301 能力，因此“永久重定向”采用静态站可实现的永久兼容契约：每个旧 URL 持续生成轻量重定向页，包含指向新 URL 的 canonical、立即 meta refresh、`location.replace` 和可点击后备链接。重定向表由单一数据文件维护，构建测试保证旧路径唯一映射到新路径且目标存在。旧 URL 不得复用为新内容，也不得在后续清理中删除。

## 12. 风险与控制

- **大规模改路径导致死链**：先建立重定向表和失败测试，再迁移文件；全量扫描 Markdown 链接和构建产物。
- **内容很多但不可查**：API/命令必须用真实名称作为三级标题，入口页提供章节索引，测试固定标题。
- **重复解释产生矛盾**：遵守单一事实源，跨章节只给调用场景和链接。
- **版本漂移**：JDK 20、MySQL 8.0 固定；Redis 和框架记录大版本/稳定文档日期，不绑定无必要的小版本。
- **若依样本偏窄**：把源码审计与官方常用能力审计拆成两份指标，任何一份通过都不能替代另一份。
- **批量生成模板化低质量内容**：分章审阅，测试拒绝空泛注释；锁、事务、安全、恢复和一致性结论必须人工复核。
- **静态重定向不等同 HTTP 301**：文档与验收明确客户端永久兼容语义，不宣称 GitHub Pages 返回 301。
