# Java 基础笔记补齐设计规范

状态：已批准，交给执行 Agent 分批实施

## 1. 背景与审计基线

`docs/courses/java` 当前是一个已经接入 VitePress 侧栏的 Java 学习路线，但文章完成度不一致。只读审计结果如下：

- 目录共有 33 个 Markdown 文件，其中 `index.md` 是课程入口页，32 个文件是课程文章。
- 目录共有 12 个章节。
- `01-Java基础/` 下前 4 篇已经有较完整正文、代码和小结，需要保留内容价值并按新模板优化。
- 其余 28 篇目前大多约 40–44 行，只有学习目标、概念提纲、实践任务、易错点和快速回顾，缺少可运行代码案例。
- 现有文章使用了不可持久化的 Markdown checkbox（例如 `- [ ]`），并把“实践任务”作为文章固定结构；静态博客页面不会为读者保存勾选状态。
- 入口页和文章路由已经被 `docs/.vitepress/config/sidebar.ts` 以 `/courses/java/` 作为前缀自动收集，文件路径是现有链接的一部分。

本设计以“面向初学者、便于日常复习”为目标：每个基础概念先给出专业术语，再用简单语言解释，并至少提供一个简单、可运行的案例；内容要帮助读者理解概念、边界和取舍，而不是堆砌 API 名称。

## 2. 目标

1. 补齐 28 篇提纲式文章，覆盖数组、文本、对象、现代类型、泛型、集合、函数式编程、I/O、网络、反射、模块、并发、JVM、工程实践和综合设计。
2. 保留并优化前 4 篇完整文章，把它们整理为后续文章可复用的内容基准；不以大规模重写为目的，不删除已有有效解释和案例。
3. 统一每篇文章的阅读结构：专业术语、白话解释、简单案例、易混点、易错点、本节小结、快速回顾。
4. 删除课程目录内的不可交互 Markdown checkbox 和“实践任务”结构，把复习清单改为普通要点式“快速回顾”。
5. 全部内容以 JDK 20 为基准；涉及 JDK 20 的预览特性或孵化 API 时，明确标注状态、编译命令和运行命令。
6. 增加自动质量检查，保证每篇文章至少有一个案例和一个“易混点”段落，并阻止 checkbox、实践任务和占位正文回归。
7. 不改变现有文章 URL、导航层级、文件名和入口链接，使补齐后的站点能够直接替换现有静态产物。

## 3. 非目标与边界

- 不新增 Java 章节或改变 12 章的学习顺序；本次只补正文和统一文章表达。
- 不引入 Spring、ORM、消息队列、分布式系统等 Java 基础路线之外的完整框架教程；它们只可作为最后的进阶出口被简短提及。
- 不把文章改成需要登录、服务端状态或前端脚本才能使用的互动课程；“快速回顾”必须是普通 Markdown 列表。
- 不升级或替换 VitePress、Vue、Node、pnpm 等站点依赖，不调整通用主题样式和侧栏组件。
- 不把 JDK 20 的预览或孵化能力写成稳定、长期兼容的 Java 标准；文章必须说明学习版本和限制。
- 本规范不实施正文、不添加测试代码、不构建或部署站点。内容、测试、最终构建、最终提交、推送和部署由执行 Agent 完成；本规范文件本身由当前设计 Agent 单独提交。

## 4. 文章统一模板

除 frontmatter 中现有的 `title`、`date`、`category`、`tags`、`description` 外，文章正文按以下顺序组织。保留现有 frontmatter 字段和现有路由，不为追求模板一致而改名或移动文件。

```markdown
# 文章标题

## 学习目标

- 读者完成本节后能做什么。
- 读者需要区分的概念或边界。
- 读者需要掌握的取舍与适用边界。

## 核心知识点

### 专业术语

用术语的英文名或 Java API 名称先定义概念，再用一两句话说明它解决什么问题。

### 白话解释与边界

说明运行时行为、使用前提、常见边界和不适用场景，避免只给名词和 API 清单。

## 简单案例

给出一个能在 JDK 20 下编译运行的最小 Java 案例，并说明关键输出或结果。

## 易混点

用直接结论或对比说明相似概念差异、异常边界和选择依据，不写成题库或问答清单。

## 易错点

- 记录本节最容易造成错误结果的使用方式。

## 本节小结

- 用 3–5 条总结本节可复述的结论。

## 快速回顾

- 使用普通无序列表列出 3–6 条可快速复习的结论。
```

模板的实施约束如下：

- 每个概念块至少出现专业术语和白话解释；涉及 API 时同时说明适用边界，不用抽象口号代替解释。
- 每篇文章至少包含一个带语言标记的 `java` 代码块作为主案例。案例应尽量短小，包含输入、关键处理和可观察输出；命令行操作可另用 `powershell` 代码块补充。
- 主案例只承担概念演示，不替换成大型项目或多文件工程。需要展示多个差异时，可在同一案例中用两三个紧邻片段说明。
- “易混点”必须给出可直接理解的结论和差异，不得写成问题清单或题库。
- “本节小结”和“快速回顾”都用可复制的普通列表，不使用 `- [ ]`、`- [x]`、`☐`、`☑` 等 checkbox 字符。
- 不再保留“实践任务”章节。需要保留实验建议时，只能在案例或“易混点”中用一两句话说明验证方法，不能变成待完成任务清单。
- 首 4 篇已有案例、表格和解释应优先保留；只补齐术语、易混点、案例输出说明和快速回顾，避免用模板替换掉有价值的上下文。
- 不使用空泛的“自行查阅”“略”“后续补充”等内容；每个章节必须在当前文章内闭合到可理解、可复述的程度。

## 5. JDK 20 与预览能力约定

全系列统一以 JDK 20 为学习、示例和命令行验证基准。文章可以介绍更高版本的演进，但不能让示例依赖 JDK 20 之后才出现的 API。使用预览特性或孵化 API 时，在案例前的提示块中明确以下信息：特性状态、JDK 20 归属、编译命令、运行命令以及它不是稳定 API 的事实。

| 能力 | JDK 20 状态 | 编译命令 | 运行命令 |
| --- | --- | --- | --- |
| `switch` 模式匹配 | 预览特性（第三次预览） | `javac --release 20 --enable-preview Example.java` | `java --enable-preview Example` |
| record patterns | 预览特性（第二次预览） | `javac --release 20 --enable-preview Example.java` | `java --enable-preview Example` |
| 虚拟线程 | 预览特性（第二次预览） | `javac --release 20 --enable-preview Example.java` | `java --enable-preview Example` |
| 结构化并发 | `jdk.incubator.concurrent` 孵化 API | `javac --release 20 --add-modules jdk.incubator.concurrent Example.java` | `java --add-modules jdk.incubator.concurrent Example` |

如果一个结构化并发案例同时使用了预览语法，则在上表的孵化模块命令上再加 `--enable-preview`；若只使用结构化并发 API，不把它误写成 preview。所有涉及预览特性的命令必须同时在编译和运行阶段体现 `--enable-preview`，编译阶段固定使用 `--release 20`，避免读者只复制一半命令而得到难以解释的错误。

- 不含明显占位或未完成标记；文章的每个核心知识点至少有术语、解释或案例中的一项可验证内容，不能把整节压缩成逗号分隔的名词列表。

### 全局一致性检查

- 课程文章和入口页的示例、命令及版本说明不引入 JDK 20 之后才提供的 API；预览能力的命令成对出现，编译和运行参数与第 5 节一致。
- `rg` 扫描课程目录时，不能发现 `实践任务` 标题、未完成 checkbox 或旧的“复习清单” checkbox 文案；入口页不能继续宣称文章固定包含实践任务。
- 统计仍为 33 个 Markdown、32 篇文章、12 个章节，防止批量编辑误删、重命名或新增未规划文件。
- 文章中的相对链接和入口页阶段路线链接仍指向存在的路径；不要求改动侧栏生成逻辑。

质量检查应给出失败文件路径和规则名称，便于执行 Agent 在同一批次内修复。测试只验证可机械判断的底线，专业准确性、案例是否足够简单、易混点表达是否清楚仍由逐篇审阅负责。

## 9. 导航兼容与发布验证

导航兼容要求如下：

- 保留 `docs/courses/java/index.md`、12 个章节目录、32 个文章文件名和所有既有 frontmatter 路径。
- 不修改 `docs/.vitepress/config/sidebar.ts` 中的 `/courses/java/` 映射；VitePress 继续从同一目录自动生成侧栏。
- 若标题从“复习清单”改为“快速回顾”，先检查仓库内是否有锚点或外部链接依赖旧标题；若存在，保留兼容锚点或同步修复链接，不改变页面路由。
- 不把文章链接改为带 `.md` 的源文件地址，不把内部链接迁移到其他课程目录。

最终发布前由执行 Agent 完成：

1. `pnpm test`：现有测试与 Java 内容质量检查全部通过。
2. `pnpm build`：VitePress 构建成功，所有 Java 路由和静态页面生成。
3. 检查构建产物存在入口页、12 章和 32 篇文章对应的页面，并抽查第一批、并发/JVM 预览案例及最后一篇综合复习页。
4. 检查 `git diff --check`、工作树文件清单和提交内容，确认没有意外改动主题、依赖、部署配置或课程之外的正文。
5. 由执行 Agent 按项目既有流程提交、推送并部署；若构建或质量检查失败，先修复并重新运行验证，再进行发布。

本设计 Agent 只提交本规范文件，不推送、不部署，也不提交文章正文或测试实现。
