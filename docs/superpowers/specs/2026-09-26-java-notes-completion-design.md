## 4. 第 01–06 章统一文章模板

除 frontmatter 中现有的 `title`、`date`、`category`、`tags`、`description` 外，已完成文章正文按以下顺序组织：

```markdown
# 文章标题

## 学习目标

- 读者完成本节后能做什么。
- 读者需要区分的概念或边界。
- 读者需要掌握的取舍与适用边界。

## 核心知识点

### 专业术语

用术语的英文名或 Java API 名称先定义概念，再用一两句话说明它解决什么问题。

### 白话解释与边界

说明运行时行为、使用前提、常见边界和不适用场景，避免只给名词和 API 清单。

## 简单案例

给出一个能在 JDK 20 下编译运行的最小 Java 案例，并说明关键输出或结果。

## 易混点

用直接结论或对比说明相似概念差异、异常边界和选择依据，不写成题库或问答清单。

## 课后小问

1. 为什么这里要区分两个相似概念？
   - 答案：用一句话给出结论。
   - 解析：补充适用边界或选择依据。

2. 什么时候不应使用本节介绍的 API？
   - 答案：用一句话给出限制条件。
   - 解析：说明替代选择或可能的错误结果。

## 本节小结

- 用 3–5 条总结本节可复述的结论。

## 快速回顾

- 使用普通无序列表列出 3–6 条可快速复习的结论。
```

实施约束：

- 每个概念块至少出现专业术语和白话解释；涉及 API 时同时说明适用边界。
- 每篇至少包含一个带语言标记的 `java` 代码块，案例尽量短小并包含输入、关键处理和可观察输出。
- “易混点”必须给出直接可理解的结论和差异；“课后小问”至少两题，每题紧跟简洁的答案和解析。
- “课后小问”“本节小结”和“快速回顾”使用可复制的普通列表，不使用 Markdown/Unicode checkbox，也不引入任务式待完成清单。
- 不使用空泛的“自行查阅”“略”“后续补充”等占位表达；每篇文章在当前范围内闭合到可理解、可复述。

## 5. JDK 20 与预览能力约定

全系列已完成内容以 JDK 20 为学习、示例和命令行验证基准。文章可以介绍更高版本的演进，但不能让示例依赖 JDK 20 之后才出现的 API。使用预览特性或孵化 API 时，在案例前明确特性状态、JDK 20 归属、编译命令、运行命令以及它不是稳定 API 的事实。

| 能力 | JDK 20 状态 | 编译命令 | 运行命令 |
| --- | --- | --- | --- |
| `switch` 模式匹配 | 预览特性（第三次预览） | `javac --release 20 --enable-preview Example.java` | `java --enable-preview Example` |
| record patterns | 预览特性（第二次预览） | `javac --release 20 --enable-preview Example.java` | `java --enable-preview Example` |
| 虚拟线程 | 预览特性（第二次预览） | `javac --release 20 --enable-preview Example.java` | `java --enable-preview Example` |
| 结构化并发 | `jdk.incubator.concurrent` 孵化 API | `javac --release 20 --add-modules jdk.incubator.concurrent Example.java` | `java --add-modules jdk.incubator.concurrent Example` |

如果结构化并发案例同时使用预览语法，则在孵化模块命令上再加 `--enable-preview`；若只使用结构化并发 API，不把它误写成 preview。预览特性的编译和运行阶段都必须体现 `--enable-preview`，编译阶段固定使用 `--release 20`。
