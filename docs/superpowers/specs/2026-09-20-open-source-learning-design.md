# 学习开源项目栏目设计

## 目标

在现有个人知识库中新增一级栏目“学习开源项目”，用于持续记录开源项目的源码阅读、架构理解和可验证实验。栏目应与现有 VitePress 内容体系自然融合，在 GitHub Pages 上保持纯静态部署，并通过克制的苹果式视觉语言提升全站质感。

## 约束与成功标准

- 不增加服务端、运行时 GitHub API、外部字体或大型前端依赖。
- 内容仍以 Markdown 为唯一事实来源；新增项目不需要修改 Vue 组件。
- `/open-source/`、项目首页和学习笔记支持直接刷新与静态构建。
- 浅色、深色、键盘操作和移动端均可用；动效尊重 `prefers-reduced-motion`。
- `pnpm build` 成功，且现有内容、CNAME 与部署方式不变。

## 信息架构

导航在“项目文档”之后新增“学习开源项目”，链接到 `/open-source/`。同时将“首页”链接修正为真实首页 `/`。

内容目录采用以下约定：

```text
docs/open-source/
├─ index.md
└─ 01-RuoYi/
   ├─ index.md
   ├─ 01-项目概览.md
   ├─ 02-目录与模块.md
   └─ 03-启动链路.md
```

项目目录的 `index.md` 通过 frontmatter 声明 `projectName`、`repo`、`summary`、`stack`、`status` 和 `order`。`status` 只允许 `learning`、`completed`、`paused`，分别显示“学习中”“已完成”“暂停”。笔记数量由构建期扫描项目目录内除 `index.md` 之外的 Markdown 文件得到。

首个项目为 RuoYi，提供项目概览、目录与模块、启动链路三篇起始笔记，内容定位为可继续扩展的学习骨架，不虚构实时仓库指标。

## 组件与数据流

`open-source.data.ts` 在构建期扫描 `docs/open-source/*/index.md`，验证并规范化 frontmatter，计算每个项目的笔记数和站内链接，然后按 `order` 与目录名稳定排序。无效状态回退为 `paused`，缺失可选字段回退为空值，确保单个项目元数据不完整时仍可构建。

`OpenSourceProjects.vue` 仅接收构建期生成的数据，渲染语义化项目卡片。整张卡片使用真实链接，仓库链接独立提供可辨识标签；卡片展示项目名、摘要、状态、技术栈和笔记数量，不请求任何运行时数据。

`docs/open-source/index.md` 使用自定义首页布局承载栏目说明与组件。项目内页继续使用 VitePress 默认文档布局，并由专用侧栏按项目目录分组。

## 视觉设计

- 系统字体栈；主品牌色使用 `#0071e3`，正文使用高对比中性色。
- 页面背景为浅灰白，内容卡为纯白/半透明面板，圆角 18–24px、细边框和克制阴影。
- 顶部导航采用半透明背景与 `backdrop-filter`，并提供纯色回退。
- 首页 Hero 精简文案，新增“学习开源项目”主要入口；功能区调整为更清晰的四个方向。
- 栏目卡片在手机一列、平板两列、桌面最多三列；悬停只做轻微位移和阴影变化。
- 深色模式使用独立表面色、边框与阴影变量，不简单反色。

## 无障碍与降级

- 所有主要导航与卡片均使用原生链接，提供清晰的 `:focus-visible`。
- 触控目标至少 44px，长标题、技术栈和路径允许换行。
- 状态同时使用文字与样式表达，不只依赖颜色。
- `prefers-reduced-motion: reduce` 时关闭非必要过渡和位移。
- 不支持 `backdrop-filter` 时保留不透明导航背景。

## 验证

- 构建期数据逻辑使用 Node 内置测试验证排序、状态映射、笔记计数和缺失字段回退。
- 运行完整 `pnpm build` 验证 SSR、路由、frontmatter 与静态输出。
- 检查构建产物包含 `/open-source/`、RuoYi 首页和三篇笔记。
- 通过浏览器检查 375px、768px、1440px，以及浅色/深色和键盘焦点状态。
