# Agent 架构图栏目设计

## 目标

在网站「前沿 & 工作」下新增「Agent 架构图」栏目，用一组按学习顺序排列的结构图帮助读者理解 Agent、RAG、MCP 及其工程化组合。

栏目是现有 Agent 开发课程的视觉辅助材料，不重复课程正文。读者可以从最小 Agent Loop 开始，逐步看到知识、工具、状态、编排、安全与 Coding Agent Harness 如何组合成完整系统。

## 用户与使用方式

面向正在按顺序学习 Agent 开发、需要建立整体结构认知的读者。

成功标准：

- 不阅读长篇说明也能看懂组件边界和数据流。
- 每张图只增加有限的新概念，不一次展示全部细节。
- 既能顺序浏览，也能从栏目首页直接跳到某个主题。
- 桌面端和手机端都能清楚阅读节点文字和箭头关系。

## 导航与路径

- 顶部导航：`前沿 & 工作 → Agent 架构图`
- 栏目首页：`/categories/agent-diagrams/`
- 图页位于：`docs/categories/agent-diagrams/`
- 图页由栏目专用侧边栏按学习顺序组织。

## 视觉语言

采用已确认的「霓虹回路」方向：深色底面、低饱和发光节点、清晰的回路和结果回填线。

颜色语义固定：

- 主决策与 Agent Loop：蓝色
- 知识、RAG 与 Context：绿色
- MCP、Tools 与外部能力：紫色
- 审批、安全与停止条件：橙色
- 普通数据、基础设施和非激活路径：中性色

颜色只用于强化分类；节点标签和线型仍要能独立表达含义，不能只靠颜色区分。

## 无标题图页

图页不显示大号文章标题、课程导语或正文标题。进入页面后，首屏直接展示结构图。

允许保留的文字只有：

- 左上角轻量序号，例如 `02 / 15`
- 小型主题标签，例如 `AGENT LOOP`
- 节点名称
- 箭头标签
- 图例
- 选中节点的一句话职责说明
- 上一张、下一张导航

用于 SEO 和 VitePress 路由的 `title` 仍保留在 frontmatter 中，但不渲染成页面内的大标题。

栏目首页同样避免传统文章式大标题，直接展示四阶段路线与十五张图的视觉入口。

## 页面结构

### 栏目首页

首页使用一条分阶段的霓虹学习路线：四个阶段沿主线路展开，每张图显示序号、短名称和微型结构预览。点击进入对应图页。

首页不显示文章卡片、摘要段落、更新时间或标签墙。

### 单图页面

每页只有一个主结构图。结构图占据内容区域的主要空间，不使用额外卡片包裹。

桌面端优先横向布局；窄屏时按组件关系重新排列为纵向结构，而不是等比例缩小整张 SVG。

节点支持悬停、键盘聚焦和点击：

- 当前节点及其直接路径高亮。
- 其他路径降低透明度，但仍保持可见。
- 图下方只显示一行当前节点职责说明。
- 再次点击空白区域恢复全图。

本轮不加入缩放画布、拖拽节点、自由编辑、动画粒子或复杂模拟控制。

## 组件设计

实现一套可复用的 Vue/SVG 图形系统，十五张图只提供结构数据，不各自复制完整样式和交互。

核心边界：

- `AgentDiagramShell`：无标题页面骨架、序号、图例、上一张/下一张。
- `ArchitectureDiagram`：渲染节点、分组、连线和选中状态。
- `DiagramNode`：节点外观、可访问标签、键盘和点击交互。
- `DiagramEdge`：请求、结果、状态和控制流四类连线。
- `diagramCatalog`：十五张图的顺序、路由、节点和边定义。
- 栏目首页组件：读取同一份 catalog，生成四阶段学习路线。

图的数据定义至少包含：节点 ID、短标签、类别、职责说明、布局槽位；连线至少包含起点、终点、流类型和可选标签。

## 连线语义

- 实线箭头：请求或主动调用
- 反向实线箭头：结果回填
- 虚线：状态、事件或观察关系
- 带门形节点的路径：审批、校验或停止条件

每张图必须明确箭头方向，不能用无方向连线表达调用流程。

## 技术约束

- 使用仓库现有 VitePress/Vue 能力和内联 SVG。
- 不依赖外部图床、在线绘图服务或运行时 API。
- GitHub Pages 静态构建后必须完全可用。
- 适配网站既有浅色/深色主题；默认视觉重点放在深色模式。
- 遵循 `prefers-reduced-motion`；不使用循环动画。
- 所有可交互节点使用语义化按钮或等价键盘行为，并提供可读的辅助文本。
- 不把 Mermaid 作为最终主要渲染方式，因为本栏目需要统一的霓虹视觉、响应式重排和路径高亮。

## 与 Agent 课程的关系

栏目只负责建立结构认知，不取代 `docs/courses/agent/`。

图中的术语、边界和调用方向必须与 Agent 课程保持一致，尤其是：

- Agent 不等于单次 LLM 调用。
- RAG 是 Context 构建能力，不是 Agent Loop 本身。
- MCP 是 Host 与外部能力之间的协议层，不负责模型决策。
- Memory、Session 和 Run State 不可混为同一概念。
- Multi-Agent 不是默认优于单 Agent。
- Guardrail、Sandbox、Approval 和 Trace 属于不同责任边界。

## 测试与验收

自动化测试锁定：

- 顶部导航存在「Agent 架构图」入口。
- 栏目首页和十五个图页路径全部存在。
- catalog 恰好包含十五张图，序号和阶段顺序正确。
- 每张图的节点 ID 唯一，连线引用的节点都存在。
- 每张图至少包含一个明确方向的主流程。
- 图页不渲染大号页面标题。
- 节点支持键盘聚焦并具有可访问名称。
- 浅色、深色和窄屏布局具有相应样式。
- `pnpm test` 与 `pnpm build` 通过。

人工验收重点：

- 首屏直接看到结构图，没有难看的大标题占位。
- 十五张图的视觉语言一致。
- 手机上文字无需缩放即可阅读。
- 节点高亮不会隐藏理解主流程所需的信息。
- 最后一张总图能准确串联前十四张图，而不是堆叠无关节点。
