# 启动链路

## 本篇目标

从 Java `main` 方法跟到 Spring Boot 创建应用上下文并启动 Web 服务，识别启动类、配置文件和自定义基础设施配置各自的作用。这里关注可从源码验证的高层顺序，不把 Spring 内部 Bean 创建细节简化成固定的单一调用链。

## 源码入口

- [RuoYi-Vue 仓库](https://gitee.com/y_project/RuoYi-Vue)
- [ruoyi-admin 启动类所在目录](https://gitee.com/y_project/RuoYi-Vue/tree/master/ruoyi-admin/src/main/java/com/ruoyi)
- [ruoyi-admin 模块 POM](https://gitee.com/y_project/RuoYi-Vue/blob/master/ruoyi-admin/pom.xml)
- [ruoyi-framework 配置目录](https://gitee.com/y_project/RuoYi-Vue/tree/master/ruoyi-framework/src/main/java/com/ruoyi/framework/config)

在当前阅读版本中，启动类是 `ruoyi-admin/src/main/java/com/ruoyi/RuoYiApplication.java`。应用配置位于 `ruoyi-admin/src/main/resources`，数据源和 MyBatis 等基础配置可从 `ruoyi-framework` 的配置类继续追踪。

## 调用链或模块关系

```text
RuoYiApplication.main(args)
  → SpringApplication.run(RuoYiApplication.class, args)
  → Spring Boot 读取环境与配置、创建应用上下文
  → 扫描 com.ruoyi 下的组件并装配各模块中的 Bean
  → 加载框架配置与应用配置，准备数据访问等基础设施
  → Web 容器启动并对外提供 Controller 定义的接口
```

这是便于阅读源码的概览。Spring Boot 会通过自动配置、配置类和依赖条件共同决定实际 Bean 的注册过程，具体执行次序应以当前版本的断点或启动日志为准。

## 核心实现

`RuoYiApplication` 使用 `@SpringBootApplication` 标记应用入口，并在 `main` 中调用 `SpringApplication.run`。当前源码显式排除了 Spring Boot 默认的 `DataSourceAutoConfiguration`；`ruoyi-framework` 中的 Druid 配置根据应用属性创建数据源，再由 MyBatis 配置注册持久层相关 Bean。这样读启动问题时，可以把“应用入口”和“基础设施具体实现”分开检查。

启动类位于 `com.ruoyi` 包下，组件扫描范围会覆盖该包下的子包。模块代码是否会被装配，还取决于它是否在应用依赖中，以及其中的组件是否满足配置条件。

## 我的理解

启动类只负责交给 Spring Boot 启动应用，不直接创建全部业务对象。启动过程的重点是类路径决定可见模块，配置和条件决定注册哪些 Bean，最后 Web 容器接管请求。排查启动问题时，我会先确认报错发生在配置读取、Bean 装配、数据源初始化还是 Web 服务启动阶段。

## 可验证实验

1. 在 `RuoYiApplication.main` 的 `SpringApplication.run` 行设置断点，观察调用返回前后应用上下文和 Web 服务的状态。
2. 查看启动类上的排除项，再搜索 `DruidConfig`、`MyBatisConfig`，确认数据源与持久层由哪些配置类负责。
3. 对照 `application.yml` 和对应环境配置，逐项确认启动所需的数据库、Redis 等外部服务；本地没有准备这些服务时，可先只做静态代码追踪。

以上目录与调用路径以当前阅读版本为参照；不同 RuoYi 版本、分支或二次开发仓库的具体路径和实现可能不同，请以本地 checkout 为准。
